# 研究执行层标准骨架

> 用于把 `nuwa-open-minis` 当前偏“规则强、执行层偏轻”的研究部分，补成更稳定的标准运行骨架。
> 目标不是机械加重流程，而是让人物型 / 复杂主题型任务在 Open Minis 中更接近原版女娲的研究执行压强。

---

## 一、适用场景
当任务属于以下任一情况时，建议启用本骨架：

- 真实人物 Skill
- 主题较大、材料较多的主题 Skill
- 需要长期维护、持续补料的 Skill
- 用户明确要求“更像原版女娲”“先调研再生成”“把研究过程也沉淀下来”

若任务很小、材料很少、用户只要快速第一版，可降级为轻量模式：
- 先生成 `SKILL.md`
- 研究骨架只保留最小版
- 不为流程完整而拖慢交付

---

## 二、目标
研究执行层要解决的不是“多写几个文件”，而是 5 件事：

1. **把研究维度固定下来**，避免每次临时想
2. **把研究结果留在 skill 目录内部**，避免研究痕迹丢失
3. **在生成前形成调研检查点**，避免空心产物
4. **在生成后形成回查与测试点**，避免看起来完整但其实变假
5. **支持后续持续补料与增量收敛**，而不是一次成稿后失去维护路径

---

## 三、推荐目录骨架
对人物型或复杂主题型任务，建议采用以下目录：

```text
[skill-name]/
├── SKILL.md
├── references/
│   ├── research/
│   │   ├── 01-writings.md
│   │   ├── 02-conversations.md
│   │   ├── 03-expression-dna.md
│   │   ├── 04-external-views.md
│   │   ├── 05-decisions.md
│   │   └── 06-timeline.md
│   └── sources-index.md
├── evaluation/
│   ├── research-checkpoint.md
│   ├── gap-audit.md
│   ├── fake-check.md
│   └── regression-review.md
└── tests/
    └── test-prompts.md
```

### 说明
- `references/research/`：按研究维度沉淀
- `references/sources-index.md`：来源索引，记录一手 / 二手 / 本地材料 / 外部补充
- `evaluation/research-checkpoint.md`：生成前调研检查点
- `evaluation/gap-audit.md`：并排评审或差距审计
- `evaluation/fake-check.md`：假像识别结果
- `evaluation/regression-review.md`：真实样本回归记录
- `tests/test-prompts.md`：压测问题与典型问法

原则：
- 目录越完整，越利于长期维护
- 但不要求所有小任务都补齐全部文件
- 优先保证 `SKILL.md` 与关键 research 文件真实存在

## 四、六路研究维度
默认优先采用以下六路研究结构：

### 1. `01-writings.md`
记录：
- 著作
- 长文
- 系统表达
- 反复出现的核心论点
- 自创术语或稳定概念

### 2. `02-conversations.md`
记录：
- 访谈
- 播客
- 问答
- 长对话
- 被追问时的应对方式

### 3. `03-expression-dna.md`
记录：
- 高频词
- 句式偏好
- 起手方式
- 切框架方式
- 节奏与叙事装置
- 不该机械模仿的噪音表达

### 4. `04-external-views.md`
记录：
- 批评者视角
- 外部评价
- 争议点
- 同行或他者如何描述其特点与盲点

### 5. `05-decisions.md`
记录：
- 关键决策
- 行动记录
- 重大转折
- 言行一致 / 不一致案例

### 6. `06-timeline.md`
记录：
- 关键时间线
- 阶段变化
- 思想转折
- 最近阶段的重要变化

## 五、四阶段检查点

### Phase 1：建目录与建占位
最少动作：
1. 创建 skill 目录
2. 创建 `SKILL.md`
3. 若任务复杂，创建 `references/research/` 基础文件

完成标准：
- 目录真实存在
- 主文件真实存在
- 更新任务已先读取旧版 `SKILL.md`

### Phase 2：调研与材料沉淀
最少动作：
1. 判断当前是本地材料模式 / 本地优先模式 / 外部补充模式
2. 把已有材料按六路研究维度沉淀
3. 标记哪些是已覆盖维度，哪些是缺失维度

完成标准：
- 至少知道当前材料覆盖了哪些维度
- 至少知道当前哪里薄弱
- 不把“搜过了”误当成“研究完成了”

### Phase 2.2：调研检查点
建议形成 `evaluation/research-checkpoint.md`，最少回答：
1. 已覆盖哪些维度？
2. 哪些维度明显偏薄？
3. 是否存在关键矛盾？
4. 当前结论以一手还是二手为主？
5. 现在直接生成，最可能假在哪？

原则：
- 该检查点不是为了拖慢交付
- 而是为了避免在材料明显不足时直接写成空心产物

### Phase 3：提炼与写主文件
最少动作：
1. 提炼心智模型
2. 提炼决策启发式
3. 提炼表达 DNA
4. 写入边界 / 反模式 / 张力
5. 回写 `SKILL.md`

完成标准：
- 主文件能运行
- 主文件能感到研究痕迹
- 关键结论不是完全外包给 research 文件

### Phase 4：生成后评估与回查
建议最少做三件事：
1. **差距审计**：与原版样本或成熟样本并排评审
2. **假像识别**：检查是否落入语录合集 / 总结报告 / 气质模仿等假像
3. **压测问答**：用典型问题试跑 Skill

若任务重要或要封板，再补：
- `evaluation/gap-audit.md`
- `evaluation/fake-check.md`
- `evaluation/regression-review.md`
- `tests/test-prompts.md`

## 七、生成后评估模板

### 1. 差距审计
重点看：
- 研究压强够不够
- 人物 / 主题有没有被点亮
- 表达 DNA 是否细到动作层
- 是否保留张力
- 是否有典型问题开口

### 2. 假像识别
重点问：
- 是不是语录合集假像？
- 是不是总结报告假像？
- 是不是气质模仿假像？
- 是不是成功学模板假像？
- 是不是研究外包假像？
- 是不是完美结构假像？

### 3. 压测问答
重点测：
- 新问题下是否还能保持该 Skill 的判断结构
- 回答是否越来越像通用 AI，而不像该 Skill
- 事实不足时是否会诚实保留边界

## 八、轻量模式与完整版模式

### 轻量模式
适用于：
- 用户只要快速第一版
- 材料很少
- 主题很窄
- 当前主要目的是先出可审稿版本

最少要求：
- `SKILL.md`
- 有最小 research 意识
- 有最小边界说明

### 完整版模式
适用于：
- 真实人物
- 重点主题
- 长期维护技能
- 用户要完整技能包
- 后续还会继续补料

建议补齐：
- `references/research/01-06.md`
- `sources-index.md`
- `evaluation/*`
- `tests/test-prompts.md`

## 九、和现有人物型体系的关系
本文件不替代以下文件，而是与其分工：

- `人物型假像识别清单.md`：负责识别“哪里假了”
- `人物型样本回归优化清单.md`：负责并排评审后怎么修
- `人物型持续喂料与增量收敛机制.md`：负责多轮补料时怎么收敛
- **本文件**：负责研究执行层怎么搭起来，避免一开始就研究层过轻

顺序建议：
1. 先用本文件搭研究执行层
2. 生成主文件后，用假像识别清单查假
3. 若仍与原版样本有差距，再做并排评审
4. 若进入多轮补料，再切到持续喂料机制

---

## 十、最终原则
- 研究执行层是为了让产物更真，不是为了让流程更重
- 目录工程化是为了让技能可维护，不是为了凑文件数量
- 检查点是为了拦住空心产物，不是为了拖慢交付
- 如果用户只要快速第一版，仍优先最短可用闭环
- 只有当任务复杂度和长期价值够高时，才把完整骨架开满
