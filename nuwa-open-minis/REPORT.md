# REPORT

## 项目名称
nuwa-open-minis

---

## 一、项目定位
这是一个 **Open Minis 专用造 Skill 系统**，用于替代原版女娲在当前环境中的不兼容部分。

核心目标：
- 不停留在技能说明层
- 不依赖 `.claude/skills` 运行时
- 优先真实落地 `SKILL.md`
- 按需补齐完整技能包

---

## 二、为什么需要它
原版女娲在当前 Open Minis 环境中主要存在以下问题：
1. 技能文档可见，但不一定进入执行态
2. 倾向展示自身 `SKILL.md`，而不是生成用户目标产物
3. 强依赖 Claude Code / skills runtime 约定
4. 难以稳定实现“先建目录、再写文件、再输出正文”

因此，`nuwa-open-minis` 的设计目标是：
> 把原版女娲的方法论骨架保留下来，同时重写其 Open Minis 执行闭环。

---

## 三、当前已经吸收的能力层

### 1. 执行层
- Open Minis 路径兼容
- 最小执行闭环
- 分段输出规则
- 失败回退规则

### 2. 提炼层
- 本地材料优先
- 材料模式判断
- 提炼检查点
- 心智模型三重筛选
- 决策启发式结构化
- 表达 DNA 提炼
- 诚实边界与质量自检

### 3. 运行层
- Response Workflow 生成规则
- 更新已有 Skill 的增量更新逻辑
- 不允许停留在说明层

### 4. 项目层
- 配套产物生成规则
- 支持 `README.md` / `REPORT.md` / `test-prompts.md`
- 强调技能包一致性

### 5. 新增工程化层
- 已补齐规范化 `test-prompts.json`
- 已有 `execution-samples.md`
- 已形成研究执行层、目录工程化、总入口调度、弱模型保下限等外挂文件体系

---

## 四、当前成熟度判断
### 当前评分建议
**96 / 100**

### 判断依据
它已经从“高可用 Beta”继续推进到“接近封板的主战造 Skill 系统”，原因包括：
- 核心执行闭环已经完整
- 方法论骨架已吸收原版女娲关键部分
- 已具备项目级产物生成能力
- 已从单主文件推进到母调度 + 外挂文件的更稳定结构
- 已补齐规范化测试资产，能支撑后续回归

### 仍未到 100 的原因
- 还缺不同题材的更系统化真实生成回归对照集
- execution samples 仍可继续做多轮对照化
- 某些长期手感问题（收束火候、变假前兆、压缩结晶感）仍无法只靠补文件解决

---

## 五、当前最值钱的状态变化
`nuwa-open-minis` 已不再只是“会生成一个 Skill 的提示词”，而是：
- 能独立运行
- 能在弱模型条件下保下限
- 能处理新建 / 更新 / 审计三类任务
- 能支撑人物型、岗位型、专题型等不同技能形态

---

## 六、当前结论
`nuwa-open-minis` 已经足够作为 Open Minis 中的主战造 Skill 系统使用。
后续优化重点不应再是继续堆规则，而应转向：
1. 真实样本回归
2. 差距点状回写
3. 主文件继续收束而不是继续膨胀
