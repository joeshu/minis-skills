# nuwa-open-minis 对标原版女娲差距审计清单（2026-04-18）

## 结论
`nuwa-open-minis` 已补到接近原版女娲的人物型蒸馏骨架，但与原版 `huashu-nuwa` 相比，仍存在 4 类差距：
1. 研究执行层
2. 目录级自包含工程化
3. 总入口分流与调度
4. 长期收束手感与变假预警的隐式经验

其中前 3 类可继续显式实现，第 4 类只能通过真实样本持续逼近，不能指望靠补几条规则一次性复制。

---

## 一、已追上的部分
对照原版 `huashu-nuwa`，`nuwa-open-minis` 已明确具备以下骨架：

- 最小执行闭环：明确要求先落地 `SKILL.md`，不允许停留在解释层
- 人物型主规则：多源交叉、批评者视角、时间线、去语录化、保留张力
- 人物锚点分层：从传记锚点 / 认知锚点推进到活体锚点
- 表达 DNA 动作层：不只写语气和句式，还写起手动作、切框架动作、拒答动作、节奏动作
- 典型问题开口：开始补“这个人会怎么开始说第一句”
- 假像识别系统：语录合集、总结报告、气质模仿、成功学模板、研究外包、完美结构等假像
- 持续喂料与增量收敛：已经不是一次成稿逻辑
- 真实样本回归：已对张一鸣 / Paul Graham / 芒格做过多人物样本验证

结论：现版已经不只是结构像女娲，而是开始具备人物型蒸馏的主工作流。

---

## 二、主要差距与判断

### 差距 1：研究执行层仍弱于原版
原版更强的地方，不只是规则，而是把研究过程写成接近生产化的执行链：

- 明确 6 路研究分工
- 明确 `references/research/01-06.md` 的沉淀结构
- 明确 Phase 1 / 1.5 / 2 / 3 检查点
- 明确生成后独立测试与对照验证
- 明确研究文件必须进入 skill 目录内部

现版虽已吸收研究维度，但更偏“高质量规则 + 手工判断”，尚未把研究链显式压成标准运行骨架。

**判断：可实现。**

### 可落地方向
- 增加统一研究目录模板
- 固化 `01-writings.md` ~ `06-timeline.md`
- 增加 Phase 1 / 1.5 / 2 / 3 检查点模板
- 增加生成前研究审查表
- 增加生成后对照测试表

---

### 差距 2：目录级自包含工程化仍弱于原版
原版强调 skill 目录复制出去仍应尽量可独立使用；研究痕迹、来源、检查点和辅助文件尽量在同目录内。

现版虽强调目录自包含，但当前真正最强的是主文件质量系统，目录级工程化标准仍偏轻。

**判断：可实现。**

### 可落地方向
建议后续对人物型 skill 目录增加稳定约定：

```text
[skill-name]/
├── SKILL.md
├── references/
│   ├── research/
│   │   ├── 01-writings.md
│   │   ├── 02-interviews.md
│   │   ├── 03-expression.md
│   │   ├── 04-external-views.md
│   │   ├── 05-decisions.md
│   │   └── 06-timeline.md
│   └── sources.md
├── evaluation/
│   ├── gap-audit.md
│   ├── fake-check.md
│   └── regression-review.md
└── tests/
    └── test-prompts.md
```

---

### 差距 3：总入口分流与调度能力仍弱于原版
原版不仅擅长明确人物，还对以下入口处理得更完整：

- 模糊需求 → 候选人物诊断
- 人物 Skill / 主题 Skill / 岗位 Skill / 更新已有 Skill
- 本地材料模式 / 本地优先模式 / 外部搜索补充模式
- 直接造稿 / 先调研 / 增量更新 三种运行模式

现版当前最强的是人物型质量系统，但作为“总造 skill 路由器”的调度能力仍未完全追平原版。

**判断：可实现。**

### 可落地方向
- 增加统一任务分流矩阵
- 补强模糊需求 → 候选人物/主题推荐流程
- 显式区分人物 / 主题 / 岗位 / 更新四种主路径
- 显式区分直接生成 / 先调研 / 增量更新三种工作模式

---

### 差距 4：长期收束手感与变假预警仍有隐式经验差距
这是当前最大差距。

原版强的不只是“知道该多源交叉”，而是更擅长：
- 什么时候该继续喂，什么时候该停
- 什么时候新材料该升成新结构，什么时候只该补证据
- 什么时候内容看起来更完整，其实正在变假
- 什么时候主文件该变厚，什么时候反而该压薄

现版已经准确摸到这一层，并补出了 3 个关键词：
- 收束判断
- 变假预警
- 材料暴涨下的主文件压缩能力

但这类能力本质上更依赖长期样本训练与真实并排评审，不是单靠补几条规则就能一次性复制。

**判断：只能持续逼近，不能承诺一次性实现。**

### 可推进方式
- 继续做真实样本并排评审
- 每轮只抓最大差距，不做全量重写
- 记录“为什么继续喂 / 为什么先收束”
- 记录“为什么这轮变假 / 如何提前识别”
- 用失败样本训练变假预警，而不是只看成功样本

## 三、实现性分栏

### A. 明确可实现
1. 研究执行层标准化
2. 目录级自包含工程化
3. 总入口分流与调度系统

### B. 可逼近但不可简单宣称完全实现
1. 收束判断
2. 变假预警
3. 材料暴涨下的主文件压缩能力
4. 原版长期隐式手感

---

## 四、建议的下一轮优先级
如果只做一轮补强，建议顺序：

1. 先补研究执行层
2. 再补目录自包含工程化
3. 再补总入口分流
4. 收束判断 / 变假预警继续走真实样本驱动，不急着再扩规则

原因：前三项最可显式落地，且能明显提高现版女娲的生产化程度；第四项更适合通过长期回归逐步逼近。

---

## 五、一句话总结
`nuwa-open-minis` 现在已经接近原版女娲的人物型蒸馏骨架；真正还差的，不是再补几条人物规则，而是：
- 研究执行层
- 目录工程化
- 总入口调度
- 长期收束手感

其中前三项能做，第四项只能持续逼近。
