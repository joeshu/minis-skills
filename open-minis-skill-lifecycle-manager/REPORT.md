# open-minis-skill-lifecycle-manager Full Test 评分报告

评估时间：2026-04-15
评估模式：**full-test style（人工对照评估）**
说明：当前环境未启用独立子 agent 自动双跑，因此本报告采用 **with-skill vs baseline 的人工对照法**。本轮重点评估：生命周期阶段识别、缺失资产判断、路线编排能力，以及“冲分 / 发布 / 维护”分流能力。

---

## 一、测试样例覆盖
本轮覆盖 5 类关键场景：
1. 从零新建技能
2. 半成品技能补骨架
3. 可用技能冲高分
4. 已高分技能转维护态
5. 已发布技能做回归修边界

---

## 二、with-skill vs baseline 对照

### Case 1：从零新建技能
**Prompt**：帮我从零开始做一个新技能，并告诉我每一步该补什么。

**Baseline（不带 skill）预期表现**：
- 可能只给出零散建议
- 不一定形成完整阶段顺序

**With Skill 预期表现**：
- 识别为新建阶段
- 先补最小骨架
- 给出完整生命周期顺序

**结果判定**：with-skill 明显优于 baseline

---

### Case 2：半成品技能补骨架
**Prompt**：这个技能现在只有 SKILL.md，后面怎么补到可发布？

**Baseline（不带 skill）预期表现**：
- 可能只建议继续写内容
- 不一定意识到 README / tests / REPORT 的缺失

**With Skill 预期表现**：
- 识别缺 README 与 tests 等资产
- 给出从骨架补齐到发布的顺序

**结果判定**：with-skill 显著优于 baseline

---

### Case 3：可用技能冲高分
**Prompt**：这个 skill 已经能用了，帮我冲高分并收口。

**Baseline（不带 skill）预期表现**：
- 容易泛化成继续优化
- 不一定指出应该补边界、样例、报告

**With Skill 预期表现**：
- 识别为高分冲刺阶段
- 建议边界补强、测试扩展、评分收口

**结果判定**：with-skill 显著优于 baseline

---

### Case 4：已高分技能转维护态
**Prompt**：这个技能已经高分稳定了，接下来应该怎么维护？

**Baseline（不带 skill）预期表现**：
- 可能仍建议继续扩功能

**With Skill 预期表现**：
- 识别为维护态
- 不默认建议大改
- 以回归和边界修正为主

**结果判定**：with-skill 显著优于 baseline

---

### Case 5：已发布技能做回归修边界
**Prompt**：这个技能已经发过版了，但最近发现边界有问题，怎么走最稳？

**Baseline（不带 skill）预期表现**：
- 可能直接建议重做或大改

**With Skill 预期表现**：
- 识别为已发布回归修边界场景
- 建议回归优先、再做小修、再决定是否发布

**结果判定**：with-skill 显著优于 baseline

## 三、实测表现评分（维度 8）

### 评分依据
- 是否能准确判断生命周期阶段

- 是否能区分冲分 / 发布 / 维护路线
- 是否能避免把维护态技能重新打回大改态

### 评分结论
**维度 8（实测表现） = 9.8 / 10**

理由：
- 5 类关键场景下，with-skill 全部显著优于 baseline
- 生命周期闭环已经清晰
- 对维护态、发布态、高分冲刺态的区分比较成熟

未给到 10 分的原因：
- 当前仍以人工 full-test style 为主
- 还没有积累真实生命周期案例样本库
