# open-minis-skill-lifecycle-manager Full Test 评分报告

评估时间：2026-04-15
评估模式：**full-test style（人工对照评估）**
评分标准：`SKILL_SCORING_STANDARD.md`
说明：当前环境未启用独立子 agent 自动双跑，因此本报告采用 **with-skill vs baseline 的人工对照法**。本轮重点评估：生命周期阶段识别、缺失资产判断、路线编排能力，以及“冲分 / 发布 / 维护 / freeze”分流能力。

## 一、测试样例覆盖
本轮覆盖 7 类关键场景：
1. 从零新建技能
2. 半成品技能补骨架
3. 可用技能冲高分
4. 已高分技能转维护态
5. 已发布技能做回归修边界
6. 技能是否适合 freeze 判断
7. 已发布技能发现问题后，判断回维护修边界还是回高分冲刺

---

## 二、with-skill vs baseline 对照

### Case 1：从零新建技能
**Prompt**：帮我从零开始做一个新技能，并告诉我每一步该补什么。

**Baseline（不带 skill）预期表现**：
- 可能只给出零散建议
- 不一定形成完整阶段顺序

**With Skill 预期表现**：
- 识别为新建阶段
- 先补最小骨架
- 给出完整生命周期顺序

**结果判定**：with-skill 明显优于 baseline

---

### Case 2：半成品技能补骨架
**Prompt**：这个技能现在只有 SKILL.md，后面怎么补到可发布？

**Baseline（不带 skill）预期表现**：
- 可能只建议继续写内容
- 不一定意识到 README / tests / REPORT 的缺失

**With Skill 预期表现**：
- 识别缺 README 与 tests 等资产
- 给出从骨架补齐到发布的顺序

**结果判定**：with-skill 显著优于 baseline

---

### Case 3：可用技能冲高分
**Prompt**：这个 skill 已经能用了，帮我冲高分并收口。

**Baseline（不带 skill）预期表现**：
- 容易泛化成继续优化
- 不一定指出应该补边界、样例、报告

**With Skill 预期表现**：
- 识别为高分冲刺阶段
- 建议边界补强、测试扩展、评分收口

**结果判定**：with-skill 显著优于 baseline

---

### Case 4：已高分技能转维护态
**Prompt**：这个技能已经高分稳定了，接下来应该怎么维护？

**Baseline（不带 skill）预期表现**：
- 可能仍建议继续扩功能

**With Skill 预期表现**：
- 识别为维护态
- 不默认建议大改
- 以回归和边界修正为主

**结果判定**：with-skill 显著优于 baseline

---

### Case 5：已发布技能做回归修边界
**Prompt**：这个技能已经发过版了，但最近发现边界有问题，怎么走最稳？

**Baseline（不带 skill）预期表现**：
- 可能直接建议重做或大改

**With Skill 预期表现**：
- 识别为已发布回归修边界场景
- 建议回归优先、再做小修、再决定是否发布

**结果判定**：with-skill 显著优于 baseline

---

### Case 6：freeze 判断
**Prompt**：这个技能现在已经很稳定了，你帮我判断是不是该进入 freeze/维护态。

**Baseline（不带 skill）预期表现**：
- 可能仍建议继续扩写
- 不一定做冻结前检查

**With Skill 预期表现**：
- 识别为 freeze 判断场景
- 先做冻结前检查
- 不默认继续扩功能

**结果判定**：with-skill 显著优于 baseline

---

### Case 7：已发布技能再治理
**Prompt**：这个技能已经发布过，但最近发现的问题不像小修，可能要回到冲高阶段，你帮我判断路线。

**Baseline（不带 skill）预期表现**：
- 容易只给出模糊建议
- 不一定区分维护修边界与重新冲高

**With Skill 预期表现**：
- 识别已发布再治理场景
- 区分维护修边界与重新冲高
- 给出路线判断

**结果判定**：with-skill 显著优于 baseline
