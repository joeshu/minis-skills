# self-improving-agent

用途：把失败、纠正、知识过时、最佳实践与功能请求整理成可复用学习记录，并控制好写入层级，避免污染长期记忆，也避免把测试联调痕迹误沉淀成正式经验。

## 默认顺序
1. 先判断值不值得记
2. 先判断这是**正式经验**还是**测试/验证记录**
3. 正式记录默认先写技能区 `data/`
4. 有明确项目上下文时可写项目级 `.learnings/`
5. 跨项目复用后再提升到 `data/public/`
6. 真正稳定后再考虑写入 Minis 长期记忆

## 什么时候建议记录
- 命令/操作失败且非显然
- 用户纠正
- 知识过时
- 外部 API / 工具失败
- 形成了更优可复用方案
- 同类问题反复出现

## 什么时候先记到测试层
- 在验证脚本是否生效
- 在测试 promote / 去重 / 回写 / 初始化机制
- 在 demo 项目里做演示
- 内容主要是“测试通过没”“版式对不对”

这类默认进入：
- `data/testing/`

而不是：
- `data/`
- `data/public/`
- Minis 长期记忆

## 什么时候不建议记录
- 普通闲聊
- 一次性小失误
- 无复用价值细节
- 用户明确说不要记录

## 记录类别
- `learning`
- `error`
- `feature`
- `testing`（仅用于机制验证/演示记录）

## 提升原则
- 跨项目可复用 → 公共区
- 能浓缩成长期规则 → Minis 长期记忆
- 临时变化 / 一次性特例 → 不要急着提升
- 复发但仍依赖具体项目上下文 → 先公共区，不急着写 Minis 记忆
- 测试/演示记录 → 默认不提升

## 公共区护栏
`data/public/` 只应保留：
- 稳定规则
- 跨项目复用经验
- 已脱离 demo / 临时目录 / 测试语境的正式条目

不应保留：
- promote 测试
- 版式测试
- 初始化测试
- demo 项目试验记录

## 入库前清洗
如果准备把该技能的数据层纳入仓库：
1. 先清理测试记录
2. 再检查公共区是否混入测试性条目
3. 不能快速判定时，默认先不提交 data，只提交脚本与规则文档

## 复发处理
- 相似问题重复出现时，优先更新已有条目而不是重复新增
- 若已是公共区规则，再次出现应先考虑更新复发次数与适用范围
