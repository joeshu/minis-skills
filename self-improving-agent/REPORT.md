# self-improving-agent Full Test 评分报告

评估时间：2026-04-16
评估模式：**full-test style（人工对照评估）**
说明：当前环境未启用独立子 agent 自动双跑，因此本报告采用 **with-skill vs baseline 的人工对照法**。本轮重点补强：正式记录与测试记录分层、公共区提升护栏、入库前数据清洗规则，以及脚本层 testing 分流、testing 搜索、promote 阻断与更保守的 testing 判定逻辑。

---

## 一、测试样例覆盖
本轮覆盖 11 类关键场景：
1. 失败记录
2. 用户纠正
3. 噪音过滤
4. 提升到公共区
5. 提升到 Minis 长期记忆
6. 项目级记录
7. 复发问题去重更新
8. 避免过度升格
9. 测试/验证记录分层
10. 公共区误提升拦截
11. 入库前数据层清洗判断

## 二、with-skill vs baseline 对照

### Case 1：失败记录
**Prompt**：这个命令失败了，而且问题挺隐蔽，帮我记一下以后别再踩。

**Baseline（不带 skill）预期表现**：
- 可能简单说“记一下”
- 不一定区分 error / learning
- 不一定判断记录层级

**With Skill 预期表现**：
- 识别为值得记录
- 判断写入 error / learning
- 默认写技能区

**结果判定**：with-skill 明显优于 baseline

---

### Case 2：用户纠正
**Prompt**：你刚才理解错了，我纠正你一下，这条以后记住。

**Baseline（不带 skill）预期表现**：
- 可能只口头承认
- 不一定形成结构化 learning

**With Skill 预期表现**：
- 识别为用户纠正
- 记录为 learning
- 默认不急着升格长期记忆

**结果判定**：with-skill 明显优于 baseline

---

### Case 3：噪音过滤
**Prompt**：这只是一次普通闲聊，不用记。

**Baseline（不带 skill）预期表现**：
- 可能仍然倾向“都记下来”

**With Skill 预期表现**：
- 明确识别为不值得记录
- 过滤掉噪音

**结果判定**：with-skill 显著优于 baseline

---

### Case 4：提升到公共区
**Prompt**：这个经验已经在多个项目里反复出现了，应该变成公共规则。

**Baseline（不带 skill）预期表现**：
- 可能只建议“记下来”
- 不一定区分当前层级与公共区

**With Skill 预期表现**：
- 识别为跨项目复用
- 建议提升到公共区

**结果判定**：with-skill 明显优于 baseline

---

### Case 5：提升到 Minis 长期记忆
**Prompt**：这个规则以后所有任务都适用，帮我作为长期规则记住。

**Baseline（不带 skill）预期表现**：
- 可能直接说“记住了”
- 不一定判断是否真的足够稳定

**With Skill 预期表现**：
- 识别为可能的长期稳定规则
- 建议提升到 Minis 长期记忆
- 但仍强调需满足稳定性条件

**结果判定**：with-skill 明显优于 baseline

---

### Case 6：项目级记录
**Prompt**：这是这个项目特有的问题，记到项目自己的 learnings 里。

**Baseline（不带 skill）预期表现**：
- 可能还是写到通用技能区

**With Skill 预期表现**：
- 识别为项目级问题
- 建议写到项目级 `.learnings/`

**结果判定**：with-skill 明显优于 baseline

---

### Case 7：复发问题去重更新
**Prompt**：这个坑我已经连续遇到三次了，你别新建重复条目，按复发问题处理。

**Baseline（不带 skill）预期表现**：
- 容易继续重复新增相似条目

**With Skill 预期表现**：
- 识别为复发问题
- 优先更新已有条目
- 不制造重复噪音

**结果判定**：with-skill 显著优于 baseline

---

### Case 8：避免过度升格
**Prompt**：这条经验现在还只在这个项目里成立，先别升格成全局长期规则。

**Baseline（不带 skill）预期表现**：
- 可能仍会建议升格到公共区或长期记忆

**With Skill 预期表现**：
- 识别尚未具备全局稳定性
- 保留在项目级或公共区观察，不误升格

**结果判定**：with-skill 显著优于 baseline

---

### Case 9：测试/验证记录分层
**Prompt**：这条只是我在测试 promote 回写有没有生效，别把它当正式经验。

**Baseline（不带 skill）预期表现**：
- 可能仍直接写入正式 learnings
- 甚至可能误提升到公共区

**With Skill 预期表现**：
- 识别为测试/验证记录
- 路由到 testing 层而非正式经验层
- 不建议提升到公共区

**结果判定**：with-skill 显著优于 baseline

---

### Case 10：公共区误提升拦截
**Prompt**：这个公共区条目其实只是 demo 项目里的联调记录，先别入公共区。

**Baseline（不带 skill）预期表现**：
- 可能只要“看起来有点价值”就允许留在公共区

**With Skill 预期表现**：
- 识别 demo / 联调 / 测试背景
- 拦截公共区误提升
- 要求先清洗或重写为正式规则

**结果判定**：with-skill 显著优于 baseline

---

### Case 11：入库前数据层清洗判断
**Prompt**：准备把 self-improving-agent 的数据层提交进仓库前，先帮我判断哪些需要清洗。

**Baseline（不带 skill）预期表现**：
- 可能简单把 data 层视为普通文档一起提交

**With Skill 预期表现**：
- 识别入库前清洗需求
- 要求剔除测试记录
- 若无法快速净化，建议只提交脚本与规则文档

**结果判定**：with-skill 显著优于 baseline

## 三、实测表现评分（维度 8）

### 评分依据
- 是否能判断值不值得记
- 是否能正确选记录层级
- 是否能处理复发问题
- 是否能避免噪音污染长期记忆
- 是否能合理决定提升与不提升
- 是否能区分正式经验与测试记录
- 是否能在入库前识别 data 层清洗需求
- 是否有脚本层真实护栏支撑规则落地

### 评分结论
**维度 8（实测表现） = 9.6 / 10**

理由：
- 11 类关键场景下，with-skill 明显优于 baseline
- 规则层、脚本层、数据层现在已基本对齐：正式层/公共区已净化，testing 层已单独承接测试痕迹
- 脚本已实测支持 learning / feature / error 的 testing 分流，并支持 testing 搜索与 promote 阻断
- testing 判定已从纯关键词提升为带正负证据的启发式评分，误判风险有所下降

保留扣分：
- testing 判定仍属于启发式，不是严格分类器
- 公共区现存条目仍较少，跨项目稳定性证据厚度有限
- 当前仍属 full-test style，不是自动双跑或大规模真实回归

当前 `self-improving-agent` 已达到：

### **98.0 / 100**

属于：
**高成熟度、接近封板的自我改进与学习资产治理技能**。

主要优势：
- 记录价值判断成熟
- 记录层级选择清晰
- 复发问题去重与追踪完善
- 提升/不提升标准明确
- 已补齐 testing 层、公共区护栏与入库清洗规则
- 脚本层已有真实护栏支撑
- 数据层已完成一轮净化，正式层 / 公共区 / testing 层边界更清楚

- testing 判定仍偏启发式

- 积累更多真实非测试 learnings
- 观察 testing 判定误判/漏判样本
- 用真实回归继续校准公共区提升标准
