# GLOBAL.md

## 隐式体系模式
- 即使用户不显式写"按体系"，默认也按当前回答风格与检索治理体系理解与执行。
- 默认执行顺序：优先遵循 `GLOBAL.md`，再按需读取 `/var/minis/shared/memory_topics/` 下相关专题，并遵循前缀、路由、冲突裁决、预算与验收规则。
- 简单问题仍保持最小读取与最短可用闭环，不因进入隐式体系模式而机械扩大读取或解释。
- 当用户显式写"按体系"时，仅表示强化显式启用；未写时，默认也按体系运行。
- 若用户当前明确要求不用这套体系、只要随意回答、或只要最原始直答，则以当前要求为准。

## 负触发（每轮自检）
- 简单确认句（"能不能""是不是""行吗"）→ 不读专题
- 单条命令或单点操作 → 不读风格文件
- 当前会话风格已锁定 → 不重复读取同类风格文件
- 主题已明确且有直达专题 → 不读 `TopicIndex.md`
- 用户当前要求与默认规则相反（"别展开""就一句话"）→ 不扩展读取

## 高频意图路由
- 命中明确意图时优先走 `IntentRouter.md`，不走全量关键词检索。
- 意图模糊时 fallback 到 `memory_get`。

## 会话级缓存
- 同一会话内首次确认风格后，标记 `style_locked`。
- 后续同类型问题直接复用已读风格文件，不重复触发 `memory_get`。
- 用户显式改前缀（如 `j:` `d: x:`）或切换任务类型时解锁重读。

## 检索与网页读取偏好
- 处理联网检索时，默认优先采用搜索类能力，而不是仅凭模型猜测。
- 处理网页内容时，默认优先选择成本更低、可验证性更高的读取路径，而不是机械截图或整页全文读取。

## 冲突兜底
- 若与系统规则或用户当前明确要求冲突，以更高优先级规则为准。

## 专题触发速查
- 回答风格、前缀协议、中文表达约束 → `ResponseStyle-AGENTS.md` / `ResponseStyle-HighDensity.md` / `ResponseModePrefixes.md`
- 检索路线、搜索源选择、网页读取路径 → 命中的相关专题或 skill（不为所有任务读取全部专题文件）
- 体系总览、分层关系、最小执行链 → `SystemArchitecture.md`
- 规则冲突、预算控制、负触发、变更准入 → `GovernanceCore.md`
- 执行优先级、任务路由、工具预算、结果落点 → `ExecutionCore.md`
- 输出验收、失败模式、主定义对照 → `QualityCore.md`
- 高频意图快捷路由 → `IntentRouter.md`
