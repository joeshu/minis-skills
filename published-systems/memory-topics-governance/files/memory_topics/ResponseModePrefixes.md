# 回答模式前缀协议

## 目的
- 用短前缀直接约束回答方式，减少模型回到默认铺垫式、扩写式输出的概率。
- 适用于中文问答、技术解释、方案比较、搜索总结、命名与选择类问题。
- 前缀只控制输出形式，不改变事实判断、工具边界与安全规则。

## 基本规则
- 用户显式写前缀时，必须按前缀执行。
- 回答模式前缀优先于一般风格偏好与排版偏好。
- 可叠加使用；若含义冲突，按从左到右、后者覆盖后者。
- 未写前缀时，仍按 `GLOBAL.md` 中的默认中文输出风格约定执行。
- 可与搜索前缀并用，如 `t:` `e:` `f:` `s:`；建议顺序为“回答模式前缀在前，搜索前缀在后”。

## 前缀速查
- `d:` 高信息密度：首句给结论；默认 3 段以内或 6 条以内；不写铺垫，不写“下一步建议”。
- `j:` 极简：默认 1~3 句；无表格、无延伸、无额外说明。
- `o:` 单方案：默认只给 1 个主方案，不列相近方案。
- `b:` 对比：先给结论，再给 2~4 条关键差异；仅在能压缩信息时使用简短表格。
- `p:` 执行：只给可执行步骤、命令、路径、改法，不补长背景。
- `x:` 禁止延伸：禁止“如果你还想”“接下来可以”“下一步建议”等收尾扩展。

## 常用组合
- `d:` 默认首选。
- `d: x:` 高信息密度 + 禁止延伸，最适合压制铺垫和收尾扩展。
- `d: o:` 高信息密度 + 单方案，适合命名、选型、决策。
- `d: p:` 高信息密度 + 执行，适合修复、操作、落地步骤。
- `d: b:` 高信息密度 + 对比，适合比较但不想看长文时。
- `j: x:` 极简 + 禁止延伸，适合只想要最短答案。

## 与搜索前缀并用
- `d: t:`：高信息密度 + Tavily 检索
- `d: o: e:`：高信息密度 + 单方案 + Exa 检索
- `j: x: f:`：极简 + 禁止延伸 + Felo 检索
- `d: x: s:`：高信息密度 + 禁止延伸 + Serper 检索

## 示例
- `d: 解释这个报错`
- `j: 这个能不能用`
- `d: o: 给我一个最稳妥方案`
- `d: b: 比较 A 和 B`
- `d: p: 直接告诉我怎么改`
- `d: x: 回答这个问题`
- `d: t: OpenMinis 官方仓库`
- `d: o: e: 某文档入口`

## 使用建议
- 不确定时，默认先用 `d:`。
- 明确不想看延伸内容时，用 `d: x:`。
- 明确只要一个答案时，用 `d: o:`。
- 明确只要操作步骤时，用 `d: p:`。
- 明确只要极短回答时，用 `j:` 或 `j: x:`。

## 注意事项
- 前缀协议会显著提高稳定性，但不是系统级绝对强制。
- 在旧对话里，历史上下文可能继续影响风格；测试前缀效果时，优先在新对话使用。
- 若用户当前明确要求详细展开，则以当前要求为准。
