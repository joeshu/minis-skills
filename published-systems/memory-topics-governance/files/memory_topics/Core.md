# Core

## 1. 执行优先级矩阵

| 任务类型 | 默认策略 |
|:---|:---|
| 可直接执行且低风险 | 先执行，再给关键说明 |
| 高风险（删除/覆盖/批量） | 先检查风险，再执行 |
| 判断型问题 | 先结论，再给最少必要依据 |
| 产物型任务 | 先落产物，再给路径与摘要 |
| 搜索/网页读取 | 先低成本检索/提取，再总结 |
| 长任务/可交接任务 | 先决定落点与 handoff |

---

## 2. 任务路由矩阵

| 任务类型 | 默认读取 | 可选补充 |
|:---|:---|:---|
| 简单事实问答 | 无 | `ResponseStyle-HighDensity.md` |
| 技术解释/报错分析 | `ResponseStyle-AGENTS.md` + `ResponseStyle-HighDensity.md` | 相关项目专题 |
| 执行类任务 | `ResponseStyle-HighDensity.md` | 项目专题、结果交付规则 |
| 搜索/联网检索 | 命中的搜索 skill | `ResponseStyle-HighDensity.md` |
| 成本优化（token/缓存/上下文/读取成本） | `Core.md` | 无 |
| 网页内容提取 | 命中的网页提取 skill 或当前页面低成本读取路径 | 搜索 skill |
| 结果交付/产物整理 | 当前任务对应交付规则 | `ResponseStyle-HighDensity.md` |
| 记忆系统维护 | 命中的记忆 skill | `Core.md` |
| Skill 设计/生命周期 | 命中的 skill 生命周期专题或 skill | 相关系统专题 |
| 命名/选型/比较 | `ResponseModePrefixes.md` + `ResponseStyle-HighDensity.md` | 领域专题 |
| 闲聊/非技术轻问答 | 无 | 无 |

### 复合任务读取顺序
- 搜索+提取+交付：先命中对应 skill/专题，再按需要补最少必要交付规则。
- 改文件+汇报：先执行路由，再补结果交付。

### 最小执行链优先
- 默认先选能闭环的最短链路，不为形式补读相邻专题。
- 明确意图命中时，优先直达对应入口，不追加体系总览文件。
- 成本优化类问题固定走 `Core.md`。
- 单轮可闭环的问题，默认不升级到 plan/review/receipt。
- 同会话已确定链路后，后续同类任务直接复用，不重复做全量 preflight。

## 3. 工具调用预算

| 操作 | 优先工具 | 次选 |
|:---|:---|:---|
| 文件读取 | `file_read` | `shell_execute` + 读取命令 |
| 文件创建 | `file_write` | — |
| 文件修改 | `file_edit` | — |
| 网页内容 | 正文/结构化提取 | DOM/JS → 截图/OCR |
| 系统操作 | `shell_execute` | — |
| 记忆读写 | `memory_get` / `memory_write` | — |

### 预算意识
- 简单任务：0~1 次工具
- 中等任务：1~3 次工具
- 复杂任务：按阶段调用，每步说明必要性
- 若某次读取/调用不会改变结论或动作，优先省略。

## 4. 结果落点策略

| 落点 | 适合 | 不适合 |
|:---|:---|:---|
| chat | 结论、摘要、即时反馈 | 主要产物、长文档 |
| `workspace/` | 当前任务工作产物、草稿 | 跨会话复用资产 |
| `shared/` | 跨会话复用、体系文件、handoff | 临时中间态 |
| `attachments/` | 图片、音频、视频 | 规则系统主资产 |
| `memory/` | 长期偏好、稳定约定 | 大段产物、临时草稿 |
| Git 镜像 | 发布版、恢复版、分享版 | 高频运行态、敏感痕迹 |

### 默认决策
- 只服务当前回答 → chat
- 需要后续继续改 → `workspace/`
- 需要跨会话复用 → `shared/`
- 媒体展示 → `attachments/`
- 长期偏好 → `memory/`
- 需要发布与恢复 → Git 镜像

## 5. 文件系统语义

| 路径 | 语义 |
|:---|:---|
| `/var/minis/workspace/` | 当前任务工作区，偏临时 |
| `/var/minis/shared/` | 跨会话共享资产区，偏稳定 |
| `/var/minis/attachments/` | 展示与媒体附件区 |
| `/var/minis/memory/` | 长期记忆区，偏好与约定 |
| Git 仓库 | 发布与恢复层 |
| chat | 即时交互层 |

### 原则
- 路径代表生命周期，不只是目录
- 工作区与共享区分离
- 记忆区与共享区分离
- 发布镜像与运行态分离

## 6. 规则优先级与冲突裁决

### 裁决顺序
1. 系统规则与安全规则
2. 用户当前消息中的显式要求
3. 用户当前消息中的回答模式前缀
4. 当前任务命中的专题文件
5. `GLOBAL.md`
6. 其他默认风格文件与一般性约定

### 关键规则
- 用户当前显式要求 > 长期偏好
- 前缀 `d:` `j:` `o:` `b:` `p:` `x:` 优先于一般风格；冲突时以后者覆盖前者
- 专题文件优先于 `GLOBAL.md`
- `GLOBAL.md` 仅在无更具体规则时生效

## 7. 回答范围与预算控制

### 核心原则
- 默认追求最短可用闭环
- 新增任何动作前，先判断是否会显著提升结果质量
- 默认优先稳定复用已有命中结果，而不是重复读取相邻规则文件

### 预算维度
| 维度 | 默认限制 |
|:---|:---|
| 回答 | 1结论段 + ≤4要点，或3段以内 |
| 读取 | 通常1个主专题；必要时+1~2补充 |
| 搜索 | 有现成信息足够时不额外搜索 |
| 网页读取 | 正文提取 > 结构化 > DOM > 截图/OCR |
| 分析分支 | 默认1条主链路 |
| 方案 | 默认1个主方案；最多补1个有取舍差异的备选 |

### 读取预算细化
| 场景 | 默认读取上限 |
|:---|:---|
| 简单确认/单句判断 | 0 |
| 单点执行/单条命令 | 0~1 |
| 明确意图且已有直达路由 | 1 |
| 中等复合任务 | 2 |
| 重任务/跨系统治理 | 3，且需说明必要性 |

### 缓存与复用规则
- 同一会话内，已命中的风格文件不重复读取。
- 同一会话内，已确定主路由后，不因用户换说法而重跑全量路由。
- 同类问题优先映射到固定入口文件，避免同义表述触发不同检索链。
- 若前一次读取已足以支持当前回答，直接复用，不为“更完整”追加读取。
- 只有当任务类型切换、用户显式改模式、或现有规则无法覆盖时，才解锁重读。

### 停止条件
- 已能直接回答核心问题
- 再增加只会更完整，不会更有用
- 继续读取只会降低缓存命中率或扩大上下文噪音

### 必须继续的条件
- 现有信息不足以支撑结论
- 不继续会导致明显错误或不可执行
- 用户明确要求更详细

## 8. 负触发规则

### 不触发场景
- 简单确认句（"能不能""是不是"）
- 单条命令或单点操作
- 当前会话风格已锁定
- 闲聊或低风险非技术问题
- 主题已明确且已有直达专题
- 用户当前要求与默认规则相反

### 触发前自检
- 读这个文件会不会改变执行方案？
- 不读它会不会明显降低结果质量？
- 读取它是否只是为了形式完整？
- 若以上都不是"会"，则不触发。

---

## 9. 规则变更与废弃

### 准入条件（新增规则至少满足一项）
- 同一失败模式重复出现2次以上
- 现有文件无法低成本吸收
- 能显著改变执行结果
- 不是现有规则的换说法
- 可被验收或回归验证

### 不应新增的情况
- 只出现一次的偶发案例
- 只是措辞润色
- 只会增加读取负担

### 废弃/合并标准
- 职责重叠度 > 70%
- 被更高层文件完全吸收
- 长期不再作为读取入口
- 继续保留只会增加理解成本
