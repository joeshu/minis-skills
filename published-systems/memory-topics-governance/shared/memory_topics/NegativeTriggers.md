# 负触发规则

## 目的
- 规定“什么时候不要触发专题读取或额外规则”，防止体系过拟合、上下文拥挤、规则滥用。

## 核心原则
- 不是命中某个词就一定读专题，而是看该专题是否会改变执行结果。
- 若读取某文件不会显著改变答案、操作路径或结果质量，就不读。

## 不触发场景

### 1. 简单确认句
- 例如：能不能、是不是、这个行吗、要不要重启。
- 默认不读取长篇风格文件与专题文件。

### 2. 单条命令或单点操作
- 用户只要一个命令、一个路径、一个参数时，不触发全套风格专题与检索专题。

### 3. 当前会话风格已锁定
- 若本会话已明确采用某输出风格，不重复读取同类风格文件。
- 例如连续多个技术问题都按高密度输出，不必每次都重读风格专题。

### 4. 闲聊或低风险非技术问题
- 不机械套用技术表达规范、检索策略、网页读取策略。

### 5. 主题已明确且已有直达专题
- 已知要读哪个专题时，不先回读 `TopicIndex.md`。

### 6. 当前问题只涉及局部补充
- 例如用户只追问“这一句什么意思”“这个参数填什么”，不重新触发整套任务路由。

### 7. 用户当前明确要求与默认专题相反
- 例如用户明确说“别展开”“别查资料”“就一句话”，则不因默认规则再扩展读取。

## 降噪原则
- 能直接回答时，不为形式补规则。
- 能直接执行时，不为形式补专题。
- 能从当前上下文判断时，不重复走索引。

## 触发前自检
- 读这个文件会不会改变执行方案？
- 读这个文件会不会避免一个高概率错误？
- 不读它会不会明显降低结果质量？
- 若以上都不是“会”，则不触发。
