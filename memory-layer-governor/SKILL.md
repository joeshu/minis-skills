# memory-layer-governor

一个用于**决定新信息该写到哪一层记忆**的执行型技能。
目标：当出现新的规则、偏好、例外、方法论、项目约定或复发模式时，判断它应该进入：
- 专题记忆
- `GLOBAL.md`
- daily memory
- 或者根本不该记

## 触发词
- 这条该记到哪里
- 这个规则写进专题还是全局
- 这个只记今天还是长期保留
- 这条值得记吗
- memory layer / write layer / which memory level

## 输入
- 一条新信息、新规则、新偏好、新例外或新经验
- 当前任务/主题上下文
- 是否已验证稳定
- 是否跨项目复用
- 是否只是近期变化

## 输出
默认返回：
1. 建议写入层级
2. 判断原因
3. 是否建议立即写入
4. 如不建议写入，说明为什么

## 记忆层级
### L0：不记录
适用：
- 普通闲聊
- 一次性小失误
- 无复用价值细节
- 用户明确说不要记

### L1：daily memory
适用：
- 近期变化
- 临时例外
- 路径调整
- 短期偏好变化
- 尚未验证稳定性的规则

### L2：专题记忆
适用：
- 某项目、站点、平台、工作流、方法论内的稳定规则
- 主题内长期复用的执行约定
- 某专题的主备忘录内容

### L3：GLOBAL.md
适用：
- 跨主题长期原则
- 通用执行偏好
- 全局安装/验证/决策边界
- 多个主题都适用的稳定规则

## 决策原则
- **先判断值不值得记**
- **本技能默认建立在“已通过写入审查”之上；若连是否该写都不明确，应回退给 `memory-write-gatekeeper`**
- **先判断稳定性，再判断作用范围**
- **近期变化优先 daily，不急着升格**
- **主题内稳定规则优先进专题**
- **跨主题长期原则才进 GLOBAL.md**
- **不确定时宁可低层记录，也不要误升格**

## 工作流

### 决策树
1. 先判断这条信息是否值得记录。
2. 若不值得，停在 L0。
3. 若值得，判断它是近期变化还是长期稳定规则。
4. 若是近期变化，优先写 daily memory。
5. 若是长期稳定规则，再判断它只属于某专题，还是跨主题通用。
6. 主题内规则 → 专题记忆；跨主题规则 → `GLOBAL.md`。

### 记录价值评分
给候选信息按证据打分：
- 用户明确要求记住：+3
- 会影响后续执行：+3
- 明显可复用：+2
- 同类问题反复出现：+2
- 只是临时细节：-2
- 普通闲聊/无复用价值：-3
- 用户明确说不要记：直接不记录

建议阈值：
- `5+`：应记录
- `3~4`：可记录，结合上下文决定
- `0~2`：一般不建议记录
- `<0`：不记录

### Phase 1: 记录价值判断
以下情况建议记录：
- 用户明确要求记住
- 新规则会影响后续执行
- 该经验可能复用
- 该变化会影响近期路径、流程、判断
- 同类问题反复出现

以下情况一般不记录：
- 普通闲聊
- 一次性无价值细节
- 明显短暂且无复用价值的信息

### Phase 2: 稳定性判断
可视为“长期稳定”的信号：
- 已在多个任务/项目复用
- 不是一次性临时特例
- 能浓缩成一句通用规则
- 短期内不太可能失效

若不满足，默认先写 daily memory。

### 稳定性评分
- 已跨多个任务复用：+3
- 能浓缩成稳定规则：+2
- 用户明确说“以后都这样”：+2
- 只是临时变化：-3
- 仍明显依赖具体上下文：-2

### Phase 3: 作用范围判断
- **只影响当前主题/项目/站点/工作流** → 专题记忆
- **影响多个主题、多个项目或全局工作方式** → `GLOBAL.md`
- **只是最近变化、临时例外、近期状态** → daily memory

### 作用范围评分
- 只在单一主题内有效：专题记忆 +3
- 跨多个主题有效：GLOBAL +3
- 明显只是最近变化：daily +3

### 建议阈值
- 稳定性分 < 2：优先 daily
- 稳定性分 >= 2 且单主题：优先专题记忆
- 稳定性分 >= 2 且跨主题：优先 GLOBAL.md

### Phase 4: 维护去向规则
- **稳定、可复用、主题内长期有效** → 专题记忆
- **跨主题共享的长期原则** → `GLOBAL.md`
- **近期变化、临时偏好、路径调整、时间线增量** → daily memory
- **不值得记或噪音信息** → 不记录

### 升格防抖规则
- 不确定时宁可先写 daily，也不要误升格到专题或 GLOBAL
- 单次出现且未验证稳定性的信息，不应直接进入 GLOBAL
- 只在一个项目内成立的长期规则，不应误写成跨主题原则

## 输出风格
- 默认一句结论：该写哪层 / 不该记
- 再补一句原因
- 不默认展开长解释

## 响应模板
### 不记录模板
- `这条暂时不建议进入记忆系统，避免增加噪音。`

### daily 模板
- `这条更像近期变化，建议先写入 daily memory。`

### 专题模板
- `这条属于主题内长期规则，建议写入对应专题记忆。`

### GLOBAL 模板
- `这条是跨主题长期原则，建议写入 GLOBAL.md。`

### 边界模板
- `这条还不够稳定，先不要升格到更高层级。`

## 维护检查清单
在决定写入层级前，优先检查：
- 这条信息是否会影响后续执行
- 它是否是近期变化还是长期规则
- 它只属于某主题，还是跨主题有效
- 它是否已经在别的层级存在类似规则
- 把它写进去会不会污染更高层级记忆

## 与其他记忆技能的分工
- `memory-layer-governor`：决定**新信息该写到哪一层**
- `memory-topic-router`：决定**任务开始前先读哪类记忆**
- `open-minis-memory-store`：负责**把分散记忆整理归并成主记忆**

## 风险与反例
- 把一次性临时变化直接写进专题或 GLOBAL
- 把跨主题原则误写成某个项目专题
- 把主题内稳定规则只写到 daily，导致长期检索不到
- 什么都记，导致记忆污染
