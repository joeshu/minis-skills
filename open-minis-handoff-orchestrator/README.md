# open-minis-handoff-orchestrator

用途：把 Minis 里的“开始前查记忆、执行中沉淀规则、结束后做 handoff”串成一个完整闭环。

## 默认顺序
1. 先用 `memory-topic-router` 查长期记忆
2. 执行中按需判断写入哪层记忆
3. 结束后用 `session-context-compactor` 生成 handoff
4. 如有必要，再用 `open-minis-memory-store` 归并长期记忆

## 适用场景
- 长任务 / 多阶段任务
- 跨会话继续执行
- 想减少上下文丢失
- 想把记忆系统与 handoff 流程串起来

## 原则
- 开始前查对记忆层级
- 执行中不乱写长期记忆
- 结束后必须有可继续执行的摘要
- 删除历史会话前必须先摘要和确认
- 当前会话压缩与长期记忆治理不要混为一步

## 风险分级
- 低风险：只查记忆或只生成 handoff
- 中风险：执行中判断记忆沉淀层级
- 高风险：删历史会话、错误升格长期规则
