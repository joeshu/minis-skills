# session-context-compactor

一个用于**压缩当前长会话上下文**的执行型技能。
目标：在不影响后续继续执行的前提下，把当前会话整理成一份**紧凑、可接续、可交接**的摘要，并在用户明确允许时再删除历史会话。

## 触发词
- 整理当前会话
- 压缩上下文
- 生成接手摘要
- 精简对话但不影响后续执行
- 删除历史会话前先整理摘要
- handoff / compact context / summarize session

## 双模式
### 模式 A：仅整理摘要
适用：
- 只想精简上下文
- 暂时不删除历史会话
- 先生成可继续执行的 handoff

### 模式 B：整理摘要 + 删除历史会话
适用：
- 用户明确要求删除历史会话
- 已确认摘要完整
- 已确认必要文件保留无误

## 输入
- 当前会话或指定任务链
- 是否需要删除历史会话
- 是否跨会话继续执行
- 当前项目主题（可选）

## 输出
默认返回：
1. 会话执行摘要
2. 必要保留文件清单
3. 下一步动作
4. 风险 / 注意事项

如果用户要求删除历史会话，还要返回：
- 删除前确认
- 删除后继续策略

## 核心原则
- **先整理，再删除**
- **必要文件必须保留**
- **删除前必须确认**
- **跨会话默认优先写入 `/var/minis/shared/`**
- **摘要必须足够支撑后续继续执行**

## 工作流

### 决策树
1. 先判断用户要的是：仅整理摘要，还是整理后删除历史会话。
2. 如果只是精简上下文：走模式 A。
3. 如果涉及删除历史会话：必须先走模式 A，再进入删除确认。
4. 如果后续要跨会话继续：摘要默认写入 `/var/minis/shared/`。
5. 如果用户特别强调“只保留后续执行必须知道的信息”：启用更强的去噪压缩模式。

### Phase 1: 确定整理范围
- 整个当前会话
- 当前项目/任务链
- 最近一段执行链路

### Phase 2: 抽取有效信息
只保留：
- 当前目标
- 关键约束
- 已完成项
- 当前状态
- 关键文件 / 路径
- 下一步动作
- 风险 / 注意事项

默认不保留：
- 闲聊
- 重复解释
- 已失效过程
- 与后续执行无关的历史噪音

### Phase 3: 识别必要保留文件
优先识别：
1. 当前会话中新建或修改过的文件
2. 当前任务链主文件（如 `SKILL.md`、`README.md`、配置文件）
3. 当前阶段生成的脚本、摘要、测试样例
4. 后续下一步会直接用到的文件

### 必要文件评分规则
给候选文件按证据打分，分数越高越优先进入“必须保留”：
- 本轮新建或修改：+3
- 当前任务主文件：+3
- 下一步会直接使用：+3
- 唯一产物或难以重建：+2
- 仅作中间草稿：-2
- 重复副本：-2
- 已失效说明：-3

建议阈值：
- `5+`：必须保留
- `3~4`：建议保留 / 人工确认
- `0~2`：可归档或不保留
- `<0`：可删除或忽略

### 必要文件判断规则
- 如果删除某文件会导致无法继续下一步，该文件必须保留
- 如果该文件是本轮唯一产物或关键脚本，应归入必须保留
- 如果该文件只是中间草稿、重复副本、已失效说明，可不作为必须保留
- 如果无法完全自动判断，至少输出人工确认清单

### Phase 4: 生成执行摘要
摘要推荐结构：
```md
# 会话执行摘要

## 当前目标
- ...

## 关键约束
- ...

## 已完成
- ...

## 当前状态
- ...

## 必要保留文件
- ...

## 下一步
- ...

## 风险 / 注意事项
- ...
```

质量要求：
- 尽量控制在 **150~400 字 / 8~20 条 bullet**
- 一条 bullet 只表达一个执行点
- 必须包含“必要保留文件”
- 读完后应能直接继续工作

### Phase 5: 选择落盘位置
- **同会话临时使用**：可写入 `/var/minis/workspace/`
- **跨会话继续使用**：默认写入 `/var/minis/shared/`

推荐目录：
- `/var/minis/shared/session-handoffs/<topic>/`
- `/var/minis/shared/<topic>/session-handoffs/`

推荐文件：
- 历史版本：`YYYYMMDD-HHMM-session-summary.md`
- 最新入口：`session-summary-latest.md`
- 如需交接版本：`handoff-latest.md`

### 落盘选择规则
- 用户提到“下次继续”“新会话继续”“跨会话继续”：默认用 shared
- 用户只说“先整理一下”：可默认用 workspace
- 如果存在旧 latest 摘要：优先更新 latest，而不是重复制造多个摘要

### Phase 6: 删除前确认（仅模式 B）
删除历史会话前必须确认：
1. 摘要是否已生成
2. 必要文件是否已列出并保留
3. 用户是否明确允许删除历史会话

确认模板：
`我已整理好执行摘要，并列出必要保留文件。如果你确认，我将删除历史会话，仅保留摘要和必要文件供后续继续执行。`

### Phase 7: 删除历史会话（仅模式 B）
在用户确认后：
- 删除历史会话
- 保留摘要文件
- 保留必要文件
- 后续从“摘要 + 文件”继续

## 风险分级
### L1：低风险
- 仅整理摘要，不删除历史会话

### L2：中风险
- 生成摘要并更新 latest 摘要文件

### L3：高风险
- 删除历史会话
- 删除前未完全确认必要文件
- 跨会话 handoff 但摘要只写在 workspace

## 成功标准
- 摘要足够支撑后续继续执行
- 必要文件清单完整
- 删除历史会话前有明确确认
- 跨会话场景默认使用 shared 路径
- 不把整段对话原样复制成摘要
- 能区分“仅整理摘要”和“整理后删除历史会话”
- 风险提示不过度冗长，但能阻止明显危险删除

## 摘要质量自检
生成摘要后至少检查：
- 是否包含 `当前目标`
- 是否包含 `关键约束`
- 是否包含 `已完成`
- 是否包含 `当前状态`
- 是否包含 `必要保留文件`
- 是否包含 `下一步`
- 是否包含 `风险 / 注意事项`
- 是否过长、接近流水账
- 是否存在整段对话照抄

- 没生成摘要就删历史会话
- 生成了摘要但漏保留关键文件
- 把整个对话原样复制成摘要
- 删除前没有确认
- 跨会话摘要只落在 workspace，导致新会话读不到

## 输出风格
- 整理摘要：简洁摘要 + 必要文件清单
- 删除前：短确认说明
- 删除后：一句后续继续策略
- 风险提示：只指出最关键的风险点

## 响应模板
### 模式 A：仅整理摘要
- 结论：`已整理当前会话并生成执行摘要。`
- 附加：必要保留文件清单
- 输出：下一步动作 + 风险提示

### 模式 B：整理后删除历史会话
- 结论：`我已整理好执行摘要，并列出必要保留文件。`
- 确认：`如果你确认，我将删除历史会话，仅保留摘要和必要文件供后续继续执行。`

### 跨会话 handoff 模板
- 结论：`我已把可继续执行的摘要写到跨会话可读取的位置。`
- 附加：shared 路径
- 输出：下次继续时优先读取的入口

### 风险模板
- 结论：`当前存在信息丢失风险。`
- 原因：只说明最关键的一条
- 下一步：给一个最直接的修复建议

## 测试要求
至少覆盖：
1. 仅整理摘要
2. 整理后删除历史会话
3. 先列出必要保留文件
4. 跨会话 handoff 落盘到 shared
5. 删除前风险检查
6. 不同项目类型摘要模板（代码项目 / 技能项目 / 文档项目）
7. 反例：摘要缺少必要文件或过度复制对话时应判为不合格
