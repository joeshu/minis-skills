# session-context-compactor

用于把当前长会话压缩成一份**可继续执行的紧凑摘要**，并在用户明确允许时，**删除历史会话**，只保留后续执行必需的文件与摘要，降低上下文负担。

## TL;DR
- **先整理，再删除**：删除历史会话前必须先生成执行摘要
- **必要文件必须保留**：不能只删对话不保留产物
- **后续继续时优先看摘要和保留文件**
- **目标是减小读取负担，不影响后续执行**

## 核心能力
### 能做
- 整理当前会话的目标、约束、决定、产物、待办
- 生成一份精简执行摘要
- 列出“必须保留的必要文件”
- 在用户允许的前提下，删除历史会话
- 让后续新会话仅依赖摘要 + 必要文件继续执行

## 双模式
### 模式 A：仅整理摘要
适用场景：
- 只想精简上下文
- 暂时不删除历史会话
- 先生成 handoff 文档备用

输出：
- 执行摘要
- 必要保留文件清单

### 模式 B：整理摘要 + 删除历史会话
适用场景：
- 用户明确想删除历史会话
- 已确认必要文件已保留
- 摘要已足够支撑后续继续执行

输出：
- 执行摘要
- 必要保留文件清单
- 删除前确认
- 删除后继续策略

### 必须保留
删除历史会话前，至少保留以下之一：
1. **执行摘要文件**
2. **本轮产出的关键文件**
3. **后续会继续用到的脚本 / 配置 / 技能文件**

### 风险点
- 如果摘要不完整、必要文件漏保留，删除历史会话后会影响后续接续执行
- 因此删除前必须先检查摘要和保留文件清单

## 0️⃣ 压缩原则
只保留以下信息：
1. **当前目标**
2. **关键约束**
3. **已完成项**
4. **当前状态**
5. **关键文件 / 路径**
6. **下一步动作**
7. **风险 / 注意事项**

默认删除或不放进摘要：
- 闲聊
- 重复解释
- 已失效过程
- 不影响后续执行的历史噪音

---

## 1️⃣ 标准输出结构

```md
# 会话执行摘要

## 当前目标
- ...

## 关键约束
- ...

## 已完成
- ...

## 当前状态
- ...

## 必要保留文件
- ...

## 下一步
- ...

## 风险 / 注意事项
- ...
```

### 质量标准
- 总长度尽量控制在 **150~400 字 / 8~20 条 bullet**
- 一条 bullet 只表达一个执行点
- 必须包含“必要保留文件”
- 读完后应能直接继续工作

---

## 2️⃣ 执行流程

### Phase A：识别范围
先确定要整理的是：
- 整个当前会话
- 当前会话中的某个项目/任务链

### Phase B：抽取有效信息
提取：
- 用户目标
- 关键偏好 / 约束
- 已做操作
- 已生成文件 / 脚本 / 技能
- 当前最新决定
- 下一步动作

### Phase C：识别必要保留文件
必须明确哪些文件要留下：
- 技能文件
- 生成脚本
- 配置文件
- 结果文档
- 任何后续继续要直接使用的文件

### Phase C.1：必要文件自动发现规则
优先识别以下文件为候选保留对象：
1. 当前会话中**新建或修改过**的文件
2. 当前任务链的主文件（如 `SKILL.md`、`README.md`、配置文件）
3. 当前阶段新生成的脚本、摘要、测试文件
4. 后续下一步明确会直接用到的文件

如果无法完全自动发现，至少要给出一份人工确认清单。

### Phase D：生成执行摘要
把有效信息压缩成唯一执行摘要，并写入文件。

如果已经存在旧摘要文件：
- 优先**更新旧摘要**，而不是重复生成多个 `session-summary.md` / `handoff.md`
- 同一主题尽量只保留 **1 份当前有效摘要**
- 旧摘要若已过时，可归档或覆盖更新

推荐路径：
- `/var/minis/workspace/session-summary.md`
- `/var/minis/workspace/handoff.md`
- `/var/minis/shared/<topic>/execution-context.md`

### Phase E：删除前确认
删除历史会话前必须确认：
- 摘要是否已生成
- 必要文件是否已列出并保留
- 用户是否明确允许删除历史会话

默认确认模板：
```text
我已整理好执行摘要，并列出必要保留文件。
如果你确认，我将删除历史会话，仅保留摘要和必要文件供后续继续执行。
```

### Phase F：删除历史会话
在用户确认后：
- 删除历史会话
- 保留摘要文件
- 保留必要文件
- 后续从摘要 + 文件继续

---

## 3️⃣ 必要文件规则

### 必须保留的文件类型
- 当前技能主文件（如 `SKILL.md`）
- 新增或修改过的关键脚本
- 当前阶段产出的摘要 / README / 测试样例
- 任何后续马上会继续使用的配置或代码文件

### 建议分类
#### A. 必须保留
- 后续继续执行直接依赖的文件
- 当前阶段唯一产出
- 无法从历史会话轻易恢复的文件

#### B. 可归档保留
- 可能有参考价值，但下一步不会立刻用到
- 中间说明文档
- 阶段性草稿

#### C. 可删除/不必保留
- 临时过程噪音
- 重复副本
- 不再影响后续执行的中间产物

### 判断标准
如果删除某文件会导致：
- 无法继续下一步
- 无法理解当前状态
- 无法复用当前成果

则该文件应归入“必须保留”。

### 不必保留的内容
- 单纯对话过程
- 已过时的中间尝试说明
- 与后续执行无关的闲聊

---

## 4️⃣ 删除前检查清单

删除历史会话前必须检查：
- 是否已有执行摘要文件
- 摘要是否足够支持后续继续执行
- 必要文件是否全部保留
- 是否还有未落盘但重要的信息
- 用户是否明确确认删除历史会话

如果任何一项不满足，先不要删。

## 4.1 摘要质量自检模板
生成摘要后，至少检查：
- 是否包含 `当前目标`
- 是否包含 `关键约束`
- 是否包含 `已完成`
- 是否包含 `当前状态`
- 是否包含 `必要保留文件`
- 是否包含 `下一步`
- 是否包含 `风险 / 注意事项`
- 是否过长、接近流水账

可用辅助脚本：
- `references/score_summary_quality.sh`

---

## 5️⃣ 反例区

### 反例 1：没生成摘要就删历史会话
问题：后续无法接续。

### 反例 2：生成了摘要，但没保留关键文件
问题：摘要知道要做什么，但没有执行材料。

### 反例 3：把整个对话复制成摘要
问题：没有真正压缩，读取负担仍然很高。

### 反例 4：删除历史会话前没有确认
问题：高风险操作，容易造成信息损失。

```md
我已整理好执行摘要，并列出必要保留文件。

```
