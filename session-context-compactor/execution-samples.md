# session-context-compactor 执行样本记录模板

用途：记录一次真实上下文压缩过程，作为 full test 与回归验证样本。

## 建议记录字段
- 日期
- 用户原始请求
- 模式（A / B）
- 是否跨会话
- 项目类型（代码 / 技能 / 文档 / 混合）
- 摘要输出路径
- 必要保留文件清单
- 是否写入 shared
- 是否需要删除确认
- 最终是否删除历史会话
- 结果质量评估
- 风险备注

## 样本模板
```md
### Sample N
- 日期：YYYY-MM-DD
- 用户原始请求：
- 模式：A / B
- 是否跨会话：是 / 否
- 项目类型：代码 / 技能 / 文档 / 混合
- 摘要输出路径：
- 必要保留文件清单：
- 是否写入 shared：是 / 否
- 是否需要删除确认：是 / 否
- 最终是否删除历史会话：是 / 否
- 结果质量评估：好 / 一般 / 差
- 风险备注：
```

## 评分用途
后续可据此观察：
- 哪类项目最容易漏保留文件
- 哪些摘要最容易过长
- 哪些场景最容易误删历史会话前提不足


### Sample 1
- 日期：2026-04-16
- 用户原始请求：做跨会话继续回归
- 模式：A
- 是否跨会话：是
- 项目类型：混合
- 摘要输出路径：`/var/minis/shared/.../handoff-latest.md`（跨会话入口）
- 必要保留文件清单：当前系统入口文档、总报告、样本索引、封板说明等 handoff 相关文件
- 是否写入 shared：是
- 是否需要删除确认：否
- 最终是否删除历史会话：否
- 结果质量评估：好
- 风险备注：验证重点从“压缩是否完成”转为“shared 入口是否足够支撑下次继续”；边界结论是跨会话场景默认 shared 仍成立，应继续保持为硬规则。

### Sample 2
- 日期：2026-04-16
- 用户原始请求：用真实删历史前案例修边界
- 模式：B
- 是否跨会话：是
- 项目类型：混合
- 摘要输出路径：先生成 handoff，再决定是否允许删除
- 必要保留文件清单：摘要文件、必要主文件、后续继续入口文件
- 是否写入 shared：是
- 是否需要删除确认：是
- 最终是否删除历史会话：否（当前轮仅做护栏回归）
- 结果质量评估：好
- 风险备注：真实回归表明“未确认摘要完整 + 未确认必要文件齐全”时必须阻止删除；删除前护栏应继续保持为强阻断，而不是提示性建议。
