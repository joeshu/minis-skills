# memory-dedup-auditor

一个用于**审计整个记忆系统是否重复、冲突、过时、层级错误**的执行型技能。
目标：在真正归并或删除记忆之前，先找出：
- 重复记忆
- 冲突记忆
- 过时记忆
- 误写到错误层级的记忆
- 应该升格或降级的记忆

## 触发词
- 记忆太乱了
- 帮我查查有没有重复记忆
- 清理记忆噪音
- 审计一下记忆系统
- 看看哪些记忆过时了
- memory audit / dedup memory / memory conflict

## 输入
- 审计范围：专题 / GLOBAL / daily / 全部
- 可选主题关键词
- 可选项目名 / 平台名 / 工作流名

## 输出
默认返回：
1. 重复项
2. 冲突项
3. 过时项
4. 层级错误项
5. 建议动作（归并 / 删除 / 降级 / 升格 / 保留观察）

## 核心原则
- **先审计，再整理**
- **不直接删除，先出报告**
- **发现问题后再决定是否交给其他技能处理**
- **宁可少删，也不要误删**

## 审计类型
### A. 重复审计
发现：
- 同义重复
- 旧规则换说法又记了一遍
- 专题 / GLOBAL / daily 里出现高度重复表达

### B. 冲突审计
发现：
- 新旧规则互相矛盾
- 同一主题出现两个相反做法
- 当前有效规则和旧规则未明确替换关系

### C. 过时审计
发现：
- 只对旧路径、旧流程、旧约定有效的记忆
- 已被新规则覆盖但仍保留的旧记忆

### D. 层级审计
发现：
- 本应是专题规则，却只留在 daily
- 本应是跨主题原则，却误写在专题
- 本应是近期变化，却误升格到 GLOBAL

## 工作流

### 决策树
1. 先确定审计范围。
2. 提取候选主题或关键词。
3. 扫描对应记忆层级。
4. 将结果分类为：重复 / 冲突 / 过时 / 层级错误。
5. 输出审计报告。
6. 如用户同意，再交给 `open-minis-memory-store` 或其他技能做整理。

### Phase 1: 确定审计范围
可选范围：
- 单个专题
- `GLOBAL.md`
- recent daily memory
- 全部记忆层级

### Phase 2: 候选检索
优先按主题、项目、平台、工作流、方法论关键词搜集相关记忆。

### Phase 3: 分类审计
#### 重复判定
- 同一规则换说法重复出现
- 同主题内重复条目
- 主题层与 daily 层重复存储

#### 冲突判定
- 两条规则结论明显相反
- 新规则已出现，但旧规则未废弃

#### 过时判定
- 规则依赖已失效路径、流程或环境
- 已被新版本覆盖

#### 层级错误判定
- 近期变化误升格
- 专题规则误写 daily
- 全局原则误写专题

### 审计判定标准
#### 重复强信号
- 核心结论一致，仅表达方式不同
- 同一主题、同一动作建议重复出现
- 已有主记忆，但 daily 里仍残留同义规则

#### 冲突强信号
- 同一主题下两个规则对同一动作给出相反结论
- 新规则已明确覆盖旧规则，但旧规则未标记废弃

#### 过时强信号
- 规则依赖的路径/仓库/流程已改变
- 已有更晚、更明确的替代规则
- 旧规则明显属于历史阶段

#### 层级错误强信号
- 临时变化写进 GLOBAL 或专题
- 主题内长期规则只留在 daily
- 跨主题原则被写到单专题文件

### Phase 4: 输出建议动作
- 重复 → 合并或删除重复项
- 冲突 → 确认当前有效版本，再更新或清理旧规则
- 过时 → 标记过时，建议归并或删除
- 层级错误 → 建议升格 / 降级 / 迁移到正确层级

### 建议动作优先级
1. 先处理冲突
2. 再处理层级错误
3. 再处理重复
4. 最后处理过时项

原因：
- 冲突最容易误导后续决策
- 层级错误会持续污染检索路径
- 重复主要制造噪音
- 过时项通常可在确认后批量处理

## 输出风格
- 默认先给审计结论摘要
- 再按四类问题列出清单
- 最后给建议动作
- 不直接动手删，除非用户进一步要求

## 响应模板
### 审计通过模板
- `我已完成记忆审计，发现以下重复 / 冲突 / 过时 / 层级问题。`

### 无明显问题模板
- `当前范围内没有发现明显重复或冲突记忆。`

### 建议整理模板
- `这些问题建议先归并/迁移后再清理，避免误删有效记忆。`

## 与其他记忆技能的分工
- `memory-dedup-auditor`：负责**查问题、出体检报告**
- `open-minis-memory-store`：负责**真正归并、清理旧记忆**
- `memory-layer-governor`：负责**判断新信息该写哪层**
- `memory-write-gatekeeper`：负责**写入前审查**
- `memory-topic-router`：负责**先读哪层记忆**

## 风险与反例
- 未审计就直接删记忆
- 只看关键词重合就误删不同主题内容
- 把近期变化误当重复长期规则
- 没确认当前有效版本就删掉旧规则
