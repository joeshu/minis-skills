# web-search

一个用于**联网网页搜索**的执行型技能。
目标：根据用户意图选择合适搜索引擎链路，在搜索失败、结果差、被拦截时自动切换，并返回**尽量可信、尽量简洁**的结果。

## 触发词
- 搜索一下 / 帮我搜 / 网上查一下 / 网页搜索
- 最新 / 现在 / 官网 / 新闻 / 实时信息
- Google / Bing / 百度 / 秘塔 / Perplexity / Tavily
- 找官网 / 找原文 / 找教程 / 找资料 / 对比多个来源

## 输入
- 用户搜索请求
- 可选偏好：中文 / 英文 / 指定搜索引擎 / 官网优先 / 只要结论 / 需要多来源对比

## 输出
默认返回：
1. 简洁结论或搜索摘要
2. 1~3 个高价值来源
3. 必要时说明搜索引擎切换情况

如用户明确要求详细结果，再返回：
- 多来源对比
- 结果摘录
- 搜索路径说明

## 搜索意图分类
先把用户请求归入以下类型之一：

### A. 深度研究 / 对比 / 趋势判断
适用：比较、趋势、优缺点、现状分析、行业观察
链路：`Perplexity -> 秘塔AI -> Bing -> Google -> Brave`

### B. 中文搜索 / 本地语境 / 中文总结
适用：中文资讯、中文讨论、国内网页、中文解释
链路：`秘塔AI -> Perplexity -> 百度 -> Bing -> Google`

### C. 官网 / 原始页面 / 入口查找
适用：官网、下载页、文档入口、原始来源
链路：`Google -> Bing -> Brave -> DuckDuckGo`

### D. 隐私优先 / 轻量搜索
适用：不强调 AI 总结，只要搜索结果页
链路：`Brave -> DuckDuckGo -> Bing`

## 引擎选择表
| 引擎 | 优势 | 常见问题 | 适合场景 |
|---|---|---|---|
| Perplexity | 总结质量高 | 可能需要登录 | 深度研究 / 总结 |
| 秘塔AI | 中文结果强 | 首页交互可能多一步 | 中文搜索 / 中文总结 |
| Google | 官网和原始页面强 | 部分地区访问体验波动 | 官网 / 原文查找 |
| Bing | 稳定、中文也不错 | 结果质量有时不如 Google | 通用 fallback |
| Brave | 轻量、稳定 | AI 总结弱 | 轻量搜索 / 备份 |
| DuckDuckGo | 轻量 | 异常页概率较高 | 隐私优先备份 |
| 百度 | 中文索引强 | 噪声偏多 | 中文网页补充 |
| 搜狗 | 微信/中文垂类较强 | 稳定性一般 | 中文补充 |
| Tavily | 面向 agent | 需 API key | 特定联网备选 |

## 工作流

### 决策树
1. 先判断用户要的是：实时信息、中文搜索、官网/原始页面、还是多来源对比。
2. 如果用户明确指定引擎：先用该引擎；失败时进入 fallback。
3. 如果用户要官网、文档、下载入口：优先官网链路。
4. 如果用户要中文总结或本地语境：优先中文链路。
5. 如果用户强调对比、趋势、现状：优先深度研究链路。
6. 如果用户强调隐私或轻量：优先隐私链路。

### Phase 1: 判断搜索目标
1. 提取核心查询词。
2. 判断用户更想要：总结、官网、原文、中文网页、还是多来源对比。
3. 选定意图类型（A/B/C/D）。

### Phase 2: 选择搜索链路
1. 按意图选择默认引擎链。
2. 如果用户明确指定引擎，则优先该引擎。
3. 如果用户说“官网 / 官方文档 / 原始链接”，优先 C 类链路。
4. 如果用户说“中文 / 国内 / 本地情况”，优先 B 类链路。

### Phase 3: 执行搜索
1. 打开首选引擎。
2. 输入查询并提取结果文本。
3. 判断是否成功。
4. 若失败或结果差，立即切换下一个引擎。
5. 首个高质量结果命中后停止；必要时补一个第二来源交叉验证。

### Phase 4: 组织输出
1. 默认先给短结论。
2. 再给 1~3 个来源链接或来源名称。
3. 如果发生 fallback，可一句话说明“已切换到备用引擎”。
4. 只有用户要求详细时，才展开多来源比较或长摘要。

## 成功标准
- 能正确识别搜索意图
- 能选择合适的搜索链路
- 遇到失败能自动 fallback
- 默认输出简洁，不堆砌无关链路细节
- 结果冲突时不会武断下结论

## 成功判定
满足至少 2 项即可视为成功：
- 页面标题或 URL 明显是结果页
- 提取文本非空，且包含有效结果
- 页面有结构化回答、结果列表、引用或相关问题
- 页面不是纯首页、纯输入框、纯验证码页

## 失败判定
以下任一出现就应切换引擎：
- 登录失效
- 验证码 / 机器人 / 异常流量提示
- 空白结果页
- 被重定向回首页
- 页面结构异常，无法提取有效文本
- 只有输入框，没有结果
- 结果明显偏题或噪声过高

## Fallback 规则
- Perplexity 未登录：切到 秘塔AI 或 Bing
- 秘塔AI 卡在首页交互：切到 百度 或 Bing
- Google 结果差：切到 Bing
- DuckDuckGo 异常页：切到 Brave 或 Bing
- 中文场景噪声高：百度与 Bing 交叉验证
- 官网搜索不准：改用 `site:` 思路重新搜一次

## 第二来源补充规则
以下场景默认应补一个第二来源进行交叉验证：
- 用户明确要求对比、趋势、现状判断
- 搜到的是新闻、公告、价格、政策、版本变化等实时内容
- 首个结果带明显总结色彩，但缺少原始来源
- 官网 / 原文查找成功后，需要再补一个搜索源确认入口稳定性
- 中文场景结果噪声较高，首个来源可信度一般
- 搜索结果彼此可能冲突，或用户明确要求“先别武断下结论”
- 代码、SDK、API、CLI、开发文档类搜索，需要避免只依赖二手教程或单一总结页

以下场景默认可不补第二来源：
- 只是找单一明确官网入口，且官方域名已清楚命中
- 用户明确说“只要一个结果”
- 低风险、低歧义、非实时的一般性网页查找

### 第二来源固定选择规则
#### 实时新闻 / 公告 / 政策 / 版本变化
- 第一来源若是 AI 总结页：第二来源优先补原始新闻站点或官方公告页
- 第一来源若是新闻站点：第二来源优先补另一家媒体或官方来源

#### 官网 / 原始页面 / 文档入口
- 第一来源命中官方域名后：第二来源优先补另一搜索引擎验证同一官方入口
- 若首个结果是聚合页或教程页：第二来源优先找官方域名，不用另一个二手来源互证

#### 中文搜索 / 本地语境
- 第一来源是秘塔AI总结：第二来源优先补百度或 Bing 的原始网页结果
- 第一来源是百度/搜狗：第二来源优先补 Bing 或 Google，降低中文噪声偏差

#### 多来源对比 / 趋势判断
- 第二来源优先选择与第一来源类型不同的来源
- 例如：AI 总结页 + 原始网页结果，或中文源 + 英文源

#### 代码 / SDK / API / CLI / 开发文档类
- 第一来源优先官方文档、官方仓库、官方发布页
- 第二来源优先顺序：
  1. 官方仓库 / 官方文档的另一入口
  2. 官方 issue / release note / changelog
  3. 高质量社区资料（如权威博客、Stack Overflow、官方论坛）
- 默认不要用两个二手教程互相验证
- 如果用户要“怎么用 / 示例代码”，优先：官方文档 + 官方仓库示例 或 官方 issue

#### 商品 / 价格 / 服务状态
- 第一来源是聚合或媒体：第二来源优先补官网定价页、状态页或官方说明

## 引擎异常模式清单
### Perplexity
- 未登录后只显示登录引导
- 页面能打开但没有有效回答内容
- 搜索结果过度摘要、缺原始来源

### 秘塔AI
- 停留在首页输入区，没有进入结果页
- 结果页加载异常，正文提取不到有效内容
- 中文答案有结构但来源不足

### Google
- 访问受限或结果异常稀少
- 结果页偏题，官网类查询却给出大量二手教程
- 地域/网络原因导致页面不可用

### Bing
- 结果稳定但排序有时不够理想
- AI 摘要可读，但原始来源入口不够靠前

### Brave
- 结果页可用但信息密度偏低
- 更适合备用，不适合作为复杂研究首选

### DuckDuckGo
- 容易出现异常页或轻量页
- 搜索结果可用，但结构化信息较少

### 百度 / 搜狗
- 中文覆盖强，但噪声、聚合页、营销页偏多
- 适合作为中文补充，不宜单独作为最终唯一依据

## 检查点
以下情况应先问一句再继续：
- 用户要“最终结论”但搜索结果相互冲突
- 用户明确要求只用某个引擎，但该引擎失效
- 搜索涉及登录态、付费墙或明显受限页面

### 确认模板
- 结果冲突：`我找到了不完全一致的结果，要不要我再补一个来源交叉验证？`
- 指定引擎失效：`你指定的引擎当前不可用，要不要我切到备用引擎继续搜？`
- 受限页面：`这个页面需要登录或受限访问，要不要我改搜公开来源？`

## 对用户的默认输出风格
- 普通搜索：先给一句结论，再给来源
- 多来源对比：先给结论，再列出主要差异
- 官网查找：先给官网/入口，再补一句判断依据
- 搜索失败：先说明失败，再给下一步建议

## 响应模板
### 普通搜索模板
- 结论：一句话回答用户问题
- 来源：1~3 个高价值来源
- 默认不展开长链路说明

### 多来源对比模板
- 结论：一句话总结主要判断
- 差异：列 2~3 条关键差异
- 来源：给主要来源

### 官网查找模板
- 先给官网/官方入口
- 再补一句“为什么判断这是官方来源”

### 失败模板
- 先说明当前引擎失败或结果不可靠
- 再说明已切备用源或建议继续交叉验证

## 失败输出模板
- `这个引擎没有给出有效结果，我已切到备用搜索源继续查。`
- `当前结果不够可靠，我建议再补一个来源交叉验证。`
- `这个页面需要登录或被拦截，我改用公开网页结果继续搜索。`

## 禁止事项
- 把单一引擎结果当作绝对结论
- 在结果明显偏题时仍强行输出
- 明明搜索失败却假装查到了
- 用户只要简短答案时输出过长链路细节
