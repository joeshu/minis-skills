技能分工

读取路由

memory-topic-router

决定任务开始前先读哪类记忆。专题优先，再回退到 GLOBAL.md 和 daily。

写入审查

memory-write-gatekeeper

决定这条信息该不该写进记忆系统，拦截噪音、敏感信息和冲突覆盖。

写入分层

memory-layer-governor

决定新信息写到哪层：不记录 / daily / 专题 / GLOBAL。

审计体检

memory-dedup-auditor

检查重复、冲突、过时、层级错误，先出体检报告，不直接删。

归并整理

open-minis-memory-store

把分散记忆整理成主记忆，清理旧项，降低噪音。

总管编排

memory-system-maintainer

识别当前问题类型，并把以上技能按合适顺序串起来。

记忆层级

层级位置适用内容
L0 不记录无闲聊、噪音、一次性无复用细节
L1 daily/var/minis/memory/YYYY-MM-DD.md近期变化、临时例外、路径调整、时间线增量
L2 专题/var/minis/shared/memory_topics/项目、站点、平台、工作流、方法论内长期稳定规则
L3 GLOBAL/var/minis/memory/GLOBAL.md跨主题长期原则、全局偏好、通用边界

推荐调用顺序

场景顺序
任务开始前先查规则memory-topic-router → 必要时补查 GLOBAL.md / daily
用户说“记住这个”memory-write-gatekeeper → memory-layer-governor → 实际写入
某主题记忆越来越乱memory-dedup-auditor → open-minis-memory-store
整套记忆系统治理memory-system-maintainer 统一编排

关系图

用户新信息
  → memory-write-gatekeeper
  → memory-layer-governor
  → 写入 daily / topic / GLOBAL

用户继续旧任务
  → memory-topic-router
  → 先读 topic / GLOBAL / daily

用户说记忆乱了
  → memory-dedup-auditor
  → open-minis-memory-store

用户要整体治理
  → memory-system-maintainer
  → 编排以上全部技能

边界提醒

  • memory-topic-router 是读之前的路由器，不是整理器。
  • memory-write-gatekeeper 是写之前的门卫，不是分层器。
  • memory-layer-governor 是分层决策器，不是审计器。
  • memory-dedup-auditor 是体检器，默认不直接删除。
  • open-minis-memory-store 是整理器，不是先验审计器。
  • memory-system-maintainer 是总管，不替代所有子技能。
