# 轻量评分框架

## 目的
- 在不引入重型打分系统的前提下，为这套体系提供半量化评估口径。
- 支持版本对比、回归评估与优化验证。

## 总分
- 总分 10 分

## 评分维度

### 1. 结论前置（0-2）
- 0：开头仍以寒暄、铺垫、复述问题为主
- 1：较早给结论，但仍夹杂明显铺垫
- 2：首句直接给结论或核心判断

### 2. 边界控制（0-2）
- 0：明显超出问题边界，附加大量未请求内容
- 1：基本收住，但仍有轻度扩展
- 2：严格围绕问题本身，不多不少

### 3. 技术完整性（0-2）
- 0：缺关键命令、路径、参数或必要 caveat
- 1：主体完整，但仍缺局部关键点
- 2：简洁且保留必要执行信息

### 4. 中文质量（0-2）
- 0：存在明显模板化、翻译腔、黑话或不自然表达
- 1：整体可读，但仍有少量不自然处
- 2：自然、准确、直接

### 5. 结构适配（0-2）
- 0：结构与任务类型明显不匹配
- 1：基本匹配，但还有机械分层或压缩过度
- 2：结构与任务目标匹配，阅读阻力低

## 使用方法
- 先过 `OutputAcceptanceChecklist.md` 验收，再看评分。
- 若验收失败，优先进入 `FailurePatterns.md` 做失配归类，而不是直接讨论分数。
- 可用于对比 baseline 与 governed 输出。
- 可用于比较不同版本规则系统下的回答质量。
- 低于 7 分时，应优先回看失败模式与验收清单。

## 注意
- 评分是辅助，不替代验收清单。
- 若出现一票否决项，即使总分不低，也视为不合格。
