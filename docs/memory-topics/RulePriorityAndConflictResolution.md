# 规则优先级与冲突裁决

## 目的
- 当多个规则源同时命中时，给出稳定、可执行的裁决顺序，避免临场猜测。
- 将“用户当前要求”“前缀协议”“专题文件”“全局默认”拉开层级，减少规则互相污染。

## 裁决总顺序
1. 系统规则与安全规则
2. 用户当前消息中的显式要求
3. 用户当前消息中的回答模式前缀
4. 当前任务命中的专题文件
5. `GLOBAL.md`
6. 其他默认风格文件与一般性约定

## 具体裁决规则

### 1. 系统规则最高优先
- 任何风格、前缀、专题、全局偏好都不能覆盖系统规则、安全规则、工具边界。
- 若用户要求与系统规则冲突，直接按系统规则执行。

### 2. 用户当前显式要求优先于长期偏好
- 用户当前明确要求“详细展开”“分步骤”“给多个方案”“只要一句话”时，优先按当前要求执行。
- 这类要求可以临时覆盖 `GLOBAL.md` 与默认专题风格，但不能覆盖系统规则。

### 3. 前缀优先于一般风格约定
- 用户显式写 `d:` `j:` `o:` `b:` `p:` `x:` 时，前缀优先于 `GLOBAL.md` 的一般风格。
- 前缀之间冲突时，按从左到右、后者覆盖前者。
- 例：`d: j:` 最终按 `j:`；`j: d:` 最终按 `d:`。

### 4. 专题文件优先于全局默认
- 当任务明显命中某专题时，应优先读取并执行该专题文件。
- 若专题文件与 `GLOBAL.md` 冲突，以专题文件在该主题内的更具体约定为准。
- 若用户当前要求与专题文件冲突，以用户当前要求为准。

### 5. 全局默认仅在无更具体规则时生效
- `GLOBAL.md` 是长期基线，不是对所有任务的机械强制。
- 没有更具体规则时，才按 `GLOBAL.md` 执行。

## 常见冲突场景

### 场景 A：高信息密度 vs 用户要求详细展开
- 结论：按用户要求详细展开。
- 但仍保留结论先行、少重复、避免模板化。

### 场景 B：极简输出 vs 技术正确性
- 结论：保技术正确性。
- 若极简会导致遗漏关键命令、路径、参数、失败条件，则必须补足。

### 场景 C：单方案前缀 vs 用户要求比较
- 结论：按用户当前比较要求执行。
- 若用户既写 `o:` 又明确说“比较 A/B”，以后者为准。

### 场景 D：多个专题同时命中
- 结论：先读与当前任务直接产出最相关的专题。
- 判定顺序：当前任务对象 > 当前动作类型 > 辅助流程专题 > 一般风格专题。
- 例：网页正文提取任务，先读 `WebPageReadingStrategy.md`，再按需参考风格文件。

### 场景 E：专题文件之间冲突
- 结论：具体专题优先于抽象专题；任务专题优先于风格专题；新近明确更新的专题优先于旧专题。
- 若仍无法裁决，优先遵循用户当前要求与最短可用闭环原则。

## 执行原则
- 不为形式一次性读取所有专题文件。
- 只读取与当前任务直接相关、且能改变执行结果的文件。
- 若当前上下文已经明确，不重复读取同一类规则文件。

## 简明判定口径
- 先看系统规则。
- 再看用户当前明确要求。
- 再看前缀。
- 再看任务专题。
- 最后才回落到 `GLOBAL.md`。
