# 结果落点策略

## 目的
- 在 OpenMinis 中，明确不同结果应该落在 chat、workspace、shared、attachments、memory 还是 Git。
- 让结果交付从“随手放”变成稳定策略。

## 核心原则
- 聊天适合最小即时反馈，不适合承载需要复用、恢复或交接的主要产物。
- 结果落点应服从：复用性、恢复性、展示性、长期性。

## 落点语义

### 1. chat
- 适合：结论、摘要、即时反馈
- 不适合：主要产物、长文档、需恢复资产

### 2. `/var/minis/workspace/`
- 适合：当前任务工作产物
- 示例：脚本、草稿、当前会话中间结果
- 特点：偏临时、偏当前任务

### 3. `/var/minis/shared/`
- 适合：跨会话复用资产、体系文件、长期项目文档、handoff、可恢复产物
- 特点：稳定、可复用、可持续维护

### 4. `/var/minis/attachments/`
- 适合：图片、音频、视频、最终展示附件
- 特点：偏展示层，不承担规则系统主资产

### 5. `/var/minis/memory/`
- 适合：长期偏好、稳定约定、需持续记住的事实
- 不适合：大段运行产物、临时任务草稿

### 6. Git 镜像
- 适合：发布版、恢复版、分享版、跨设备同步版
- 不适合：高频运行态、daily memory、敏感运行痕迹

## 默认决策
- 若结果只服务当前回答：留在 chat
- 若结果需要后续继续改：落 `workspace/`
- 若结果需要跨会话复用：落 `shared/`
- 若结果是媒体展示：落 `attachments/`
- 若结果是长期偏好：落 `memory/`
- 若结果需要发布与恢复：进入 Git 镜像

## 与其他文件的关系
- 与 `ExecutionPriorityMatrix.md` 配合：先决定做什么，再决定落哪里。
- 与 `OpenMinisFilesystemSemantics.md` 配合：后者提供路径语义，本文件给落点策略。
