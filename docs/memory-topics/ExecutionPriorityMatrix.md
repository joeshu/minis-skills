# 执行优先矩阵

## 目的
- 定义在 OpenMinis 中，哪些任务默认应先执行，哪些任务默认应先解释，哪些任务默认应先产出文件。
- 把“执行优先”从风格偏好提升为显式治理规则。

## 核心原则
- 在 OpenMinis 中，可执行任务默认优先执行闭环，而不是解释闭环。
- 若执行结果本身就是最有价值的信息，则先做结果，再补最少必要说明。
- 若任务风险高、前提不明或不可逆，则先澄清或先做低风险检查。

## 任务类型矩阵

### 1. 可直接执行且低风险任务
- 默认：**先执行**
- 示例：改文件、生成报告、同步目录、导出数据、运行检查命令
- 输出：先给结果，再补关键说明

### 2. 高风险执行任务
- 默认：**先检查，再执行**
- 示例：删除、覆盖、强推、批量移动、恢复覆盖
- 输出：先给风险与检查结果，再进入执行

### 3. 判断型问题
- 默认：**先判断**
- 示例：这两个方案哪个好、这个系统有什么问题、这段话是否合理
- 输出：先结论，再给最少必要依据

### 4. 产物型任务
- 默认：**先产文件**
- 示例：写 Markdown、HTML、脚本、配置、报告
- 输出：先落产物，再给路径与摘要

### 5. 搜索 / 网页读取任务
- 默认：**先低成本检索 / 提取，再总结**
- 输出：先拿到可验证内容，再给判断

### 6. 长任务 / 可交接任务
- 默认：**先决定落点与 handoff**
- 输出：执行同时考虑 shared / handoff / Git 镜像，而不是只停留在聊天里

## 执行前检查
- 是否真能直接执行而不需要补关键信息
- 是否存在明显不可逆风险
- 是否应先决定结果落点
- 是否用户真正想要的是结果，而不是解释

## 与其他文件的关系
- 与 `TaskRoutingMatrix.md` 配合：后者决定读什么，本文件决定先做什么。
- 与 `ResultPlacementPolicy.md` 配合：本文件决定动作优先级，后者决定结果落点。
- 与 `ToolInvocationBudget.md` 配合：本文件决定执行方向，后者决定工具成本路径。
