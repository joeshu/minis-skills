# 规则变更准入机制

## 目的
- 限制规则系统无边界膨胀。
- 只有当某个问题具备足够稳定性、重复性或显著收益时，才允许升格为系统规则。

## 核心原则
- 先看能否被现有文件吸收。
- 先看是否只是样本问题，而不是系统问题。
- 先看新增规则是否真的改变执行结果。

## 准入条件
新增规则至少应满足以下一项：
1. 同一失败模式已重复出现 2 次以上。
2. 现有文件无法低成本吸收。
3. 新规则能显著改变执行结果、读取路径或输出质量。
4. 新规则不是现有规则的换说法重写。
5. 新规则可以被验收层或回归样本层验证。

## 不应新增为规则的情况
- 只出现一次的偶发案例。
- 已可由样本层记录的问题。
- 只是措辞润色而无执行增益的内容。
- 只是为了看起来更完整而补的抽象说法。
- 可通过修改现有文件一句话吸收的问题。

## 变更决策顺序
1. 这是样本问题还是系统问题？
2. 现有文件能否吸收？
3. 若不能吸收，是否值得新建文件？
4. 若值得新建，是否已有对应索引、metadata、验收与回归入口？

## 推荐动作
- 偶发问题：先写入 `RegressionCases.md`
- 失配模式：优先补 `FailurePatterns.md`
- 验收口径缺失：优先补 `OutputAcceptanceChecklist.md`
- 真正新增层级：才考虑新增专题或治理文件

## 一票否决
- 不能验证的新规则
- 与现有规则明显重复的新规则
- 只会增加读取负担、不会提高结果质量的新规则
