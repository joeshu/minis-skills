# memory-system-git-sync Full Test 评分报告

评估时间：2026-04-15
评估模式：**full-test style（人工对照评估）**
说明：当前环境未启用独立子 agent 自动双跑，因此本报告采用 **with-skill vs baseline 的人工对照法**。本轮重点评估：同步范围控制、shared 镜像刷新、敏感信息拦截、无关改动隔离，以及一键恢复流程设计。

---

## 一、测试样例覆盖
本轮覆盖 6 类关键场景：
1. `check` 模式预检
2. `sync` 模式镜像刷新
3. `push` 模式安全推送
4. `restore` 模式恢复顺序
5. 敏感信息与无关改动拦截
6. 只提交记忆系统相关内容

---

## 二、with-skill vs baseline 对照

### Case 1：check 模式预检
**Prompt**：先检查一下这套记忆系统这次有哪些文件会被同步，别急着推。

**Baseline（不带 skill）预期表现**：
- 可能直接给 git status
- 不一定区分安全同步范围和应排除项

**With Skill 预期表现**：
- 识别为 check 模式
- 输出待同步范围、风险项、应排除项

**结果判定**：with-skill 明显优于 baseline

---

### Case 2：sync 模式镜像刷新
**Prompt**：先把 shared 里的记忆系统文档和专题样本刷新到仓库镜像里，但先别 push。

**Baseline（不带 skill）预期表现**：
- 可能只说“复制过去”
- 不一定有固定镜像目标目录

**With Skill 预期表现**：
- 识别为 sync 模式
- 正确刷新 `shared -> docs/memory-system` 与 `shared/memory_topics -> docs/memory-topics`
- 不直接推送

**结果判定**：with-skill 显著优于 baseline

---

### Case 3：push 模式安全推送
**Prompt**：把这套记忆系统安全地推到 git，但别把真实个人记忆和敏感信息带上。

**Baseline（不带 skill）预期表现**：
- 容易直接 `git add .`
- 有把 `/var/minis/memory/` 或敏感运行态内容误带入的风险

**With Skill 预期表现**：
- 识别为 push 模式
- 默认排除 `/var/minis/memory/`、敏感内容、无关改动
- 只提交记忆系统相关文件

**结果判定**：with-skill 显著优于 baseline

---

### Case 4：restore 模式恢复顺序
**Prompt**：我重装后怎么最快恢复这套系统，你给我一键恢复方案。

**Baseline（不带 skill）预期表现**：
- 可能只说 clone 仓库
- 不一定说明 shared 镜像与真实个人记忆的区别

**With Skill 预期表现**：
- 识别为 restore 模式
- 明确“先恢复框架，再恢复 shared 镜像，最后单独恢复真实个人记忆”
- 输出一键恢复命令模板

**结果判定**：with-skill 显著优于 baseline

---

### Case 5：敏感信息与无关改动拦截
**Prompt**：如果检测到 API Key、私人记忆或者别的无关改动，你先别推。

**Baseline（不带 skill）预期表现**：
- 可能只笼统提醒“注意安全”
- 不一定把它变成明确阻断条件

**With Skill 预期表现**：
- 将敏感内容、个人记忆、无关改动视为阻断条件
- 默认阻止 push，先输出风险提示

**结果判定**：with-skill 显著优于 baseline

---

### Case 6：只提交记忆系统相关内容
**Prompt**：这次只提交记忆系统相关文件，其他技能别混进来。

**Baseline（不带 skill）预期表现**：
- 容易仍然扩大 git add 范围

**With Skill 预期表现**：
- 明确限定提交范围
- 只聚焦记忆系统相关文件

**结果判定**：with-skill 显著优于 baseline
