# memory-write-gatekeeper

一个用于**写入记忆前先做审查**的执行型技能。
目标：在真正写入记忆之前，先判断这条信息：
- 值不值得记
- 会不会污染记忆系统
- 是否太临时 / 太依赖上下文
- 是否需要用户确认
- 是否和已有记忆重复或冲突

## 触发词
- 记住这个
- 以后按这个做
- 帮我保存一下
- 这条经验以后别忘
- 帮我记下来
- save this to memory / remember this / keep this rule

## 输入
- 一条准备写入记忆的信息
- 当前任务上下文
- 是否涉及长期偏好 / 长期规则 / 临时变化 / 敏感信息
- 是否已有相似记忆

## 输出
默认返回：
1. 是否建议写入
2. 不建议时的原因
3. 建议写入时是否需要确认
4. 若可写入，再交给下一步技能决定写到哪层

## 核心原则
- **先判断要不要写，再判断写到哪**
- **宁可少写，也不要污染长期记忆**
- **涉及敏感或高影响规则时先确认**
- **发现冲突时优先更新旧规则，不盲目新增**

## 工作流

### 决策树
1. 先判断这条信息是否有中长期价值。
2. 若没有，直接拦截，不建议写入。
3. 若有，再判断它是否过于临时、依赖当前上下文、或可能与旧记忆冲突。
4. 若涉及敏感信息、高影响偏好或覆盖旧规则，先要求确认。
5. 审查通过后，再交给 `memory-layer-governor` 决定写到哪一层。

### 记录价值评分
给候选信息按证据打分：
- 用户明确要求长期记住：+3
- 会影响多个后续任务：+3
- 明显可复用：+2
- 属于稳定偏好/工作流：+2
- 同类问题反复出现：+2
- 只是一次性细节：-2
- 只在当前上下文成立：-2
- 普通闲聊/无复用价值：-3
- 用户明确说不要记：直接不记录

建议阈值：
- `5+`：可通过写入审查
- `3~4`：可暂缓，视上下文与稳定性决定
- `0~2`：一般不建议写入
- `<0`：不写入

### Phase 1: 价值判断
建议写入：
- 会影响后续多个任务的规则
- 稳定偏好
- 可复用工作流
- 反复出现的经验
- 用户明确要求长期记住

一般不建议写入：
- 普通闲聊
- 一次性情绪表达
- 今天临时变化
- 过度依赖当前上下文的小细节
- 无法复用的偶发信息

### Phase 2: 污染风险判断
以下情况要谨慎：
- 信息只在当前任务里成立
- 语义模糊，无法转成明确规则
- 可能明天就失效
- 跟已有记忆说法冲突
- 属于未确认的推测

### Phase 3: 确认要求判断
以下情况建议先确认：
- 准备写成长期偏好
- 准备写进 GLOBAL.md
- 会改变很多后续默认行为
- 涉及敏感信息
- 与已有规则冲突，且需要覆盖旧规则

### Phase 4: 冲突与重复判断
发现以下情况时，不要盲目新写：
- 已有相似规则
- 已有同主题旧规则
- 当前信息只是旧规则的小变体

优先动作：
- 若是旧规则更新：建议更新旧记忆
- 若是重复表达：不新增
- 若是冲突：要求确认是否覆盖旧规则

### 冲突强度判断
- 仅措辞不同、结论相同：视为重复，不新增
- 结论不同但可并存：建议补充说明，不直接覆盖
- 结论明显相反：视为冲突，必须确认后再更新

### Phase 5: 敏感信息护栏
以下信息默认不直接写入记忆：
- 密码、Token、API Key、验证码、私钥
- 可能泄露隐私或安全边界的敏感信息
- 未经用户明确确认的高风险个人信息

如用户坚持写入敏感信息：
- 必须先提醒风险
- 默认仍建议不要写

### Phase 6: 通过后交给下一层
通过审查后：
- 交给 `memory-layer-governor` 决定写入层级
- 如属于已有主题旧记忆更新，再交给 `open-minis-memory-store` 或对应维护流程

## 判断标准
### 值得写入的强信号
- “以后都这样”
- “这是长期偏好”
- “多个任务都会用到”
- “这是固定工作流”
- “以后提醒我按这个规则做”

### 不值得直接写入的强信号
- “这次先这样”
- “今天临时改一下”
- “只是顺手说一句”
- “只是这轮任务里的局部特例”

## 输出风格
- 默认一句结论：建议写 / 不建议写
- 再补一句原因
- 如果需要确认，再补确认问题
- 不默认展开大段分析

## 响应模板
### 通过模板
- `这条适合进入记忆系统，下一步应再判断写到哪一层。`

### 拦截模板
- `这条暂时不建议写入记忆，避免污染长期记忆。`

### 确认模板
- `这条会影响后续默认行为，建议确认后再写入。`

### 冲突模板
- `这条与已有记忆可能冲突，建议先确认是否覆盖旧规则。`

## 与其他记忆技能的分工
- `memory-write-gatekeeper`：负责**写入前审查：该不该写**
- `memory-layer-governor`：负责**决定写到哪一层**
- `memory-topic-router`：负责**任务开始前先读哪类记忆**
- `open-minis-memory-store`：负责**整理、归并、清理旧记忆**

## 风险与反例
- 听到“记住”就直接写，导致记忆污染
- 把一次性变化写成长期规则
- 未确认就覆盖旧规则
- 明显依赖上下文的信息被误写入长期记忆
- 本应更新旧记忆，却错误新增重复条目
