# open-minis-memory-store

用于把**分散的同类记忆**（某个项目、某类偏好、某组规则、某个长期主题）整理成**一个唯一主记忆**，并删除其他重复、过时、零散的相关记忆，降低记忆噪音。

## TL;DR
- **一个主题只保留一个主记忆**
- **先查全量相关记忆，再合并整理**
- **删除旧记忆前必须先备份 memory 文件**
- **默认删除重复/过时/被合并的相关记忆**
- **敏感信息仍然禁止写入主记忆**

## 快速决策树
- **只是新增一条长期偏好** → 不一定需要归并，先普通写入
- **同一主题已有多条零散记忆** → 触发本技能，整理成单一主记忆
- **用户明确要求删旧记忆** → 先归并出主记忆，再删除其他相关记忆
- **无法安全定位旧记忆块** → 只生成主记忆，不自动删除

## 触发词
- 把这些记忆整理成一个
- 合并相关记忆、清理重复记忆、删除旧记忆
- 把某个项目的记忆收拢一下
- 整理 Minis 记忆、记忆归并、记忆去重
- consolidate memories, merge memory entries, clean old memories

## 适用场景
- 某个项目积累了多条零散记忆，需要整理成项目总备忘录
- 某类用户偏好分散在多天日志里，需要统一成一条主规则
- 某套工作流/验证规范多次迭代后，需要保留最新版并删除旧版本
- 某个主题有很多相似记忆，需要去重、合并、降噪

## 不适用场景
- 单条全新记忆的简单写入
- 只有临时会话信息，没有长期价值
- 敏感信息、凭证、密钥、Token、私钥、验证码
- 用户未允许清理旧记忆时的强制删除

## 0️⃣ 核心原则

### 0.1 单主题单主记忆
对同一个主题，最终目标是只保留：
- **1 条主记忆**：作为后续检索的唯一权威版本
- 删除其他重复、过时、被合并的记忆

### 0.2 主记忆必须满足
- 标题清晰
- 内容可复用
- 包含当前最新规则/偏好/结论
- 尽量不依赖当时会话语境
- 长度适中，避免变成冗长流水账

### 0.3 删除原则
以下记忆应优先删除：
1. 与主记忆重复
2. 已被新版本覆盖
3. 只是中间过程记录，没有长期价值
4. 会误导后续检索结果

## 1️⃣ 总体流程

### Phase A：确定主题边界
先明确这次要整理的是：
- 某个**项目**（如 `opencode2api-enhanced`）
- 某类**偏好**（如“文件修改前先备份”）
- 某组**工作规则**（如验证方式、提交流程）
- 某个**长期主题**（如家庭设备、常用仓库、固定任务流程）

如果主题边界不清，先问用户：
- “你是要整理整个项目记忆，还是只整理其中某一类规则/偏好？”

### Phase B：全量检索相关记忆
1. 提取 2~6 个稳定关键词
2. 用 `memory_get` 搜索相关记忆
3. 记录匹配结果来自哪些文件/日期
4. 按以下类型分组：
   - 当前仍有效
   - 已过时
   - 重复表达
   - 值得并入主记忆

### Phase C：生成主记忆草稿
将相关记忆压缩成一个统一结构：

```md
## 主题总备忘录
- 当前有效规则 1
- 当前有效规则 2
- 关键偏好/结论 3
- 若有必要，补充“已废弃/不再使用”的说明
```

### Phase D：确认是否清理旧记忆
整理型操作默认会**删除其他相关旧记忆**，因此必须确认：
- 要不要删除重复项
- 要不要删除旧版本
- 要不要保留历史痕迹

默认确认模板：
```text
我会把相关记忆整理成 1 条主记忆，并删除其他重复/过时记忆。
删除前会先备份相关 memory 文件。
请确认是否继续。
```

### Phase E：备份 memory 文件
在删除前，必须先备份相关 memory 文件：
- 读取匹配到的 memory 文件
- 复制为 `.bak-时间戳`
- 再执行删除/归并

### Phase F：写入主记忆 + 删除旧记忆
1. 先判断该主题是否**已经存在主记忆**
2. 若已存在主记忆：优先**更新主记忆**，而不是重复新建第二条主记忆
3. 若不存在主记忆：再用 `memory_write` 创建新的主记忆
4. 对匹配到的旧记忆文件：
   - 用 `file_read` 找出相关旧块
   - 用 `file_edit` 精确删除旧记忆块
5. 保留唯一主记忆，清除其他相关旧记忆

## 2️⃣ 删除与归并规则

### 2.0 删除范围最小化
清理时遵循“**最小必要删除**”原则：
- 只删除与当前主题直接相关的旧记忆
- 不因关键词模糊命中而误删其他项目记忆
- 如果某条记忆只是包含相似词，但主题不同，默认不删
- 宁可少删，也不要误删

### 2.1 直接删除
满足以下条件可直接删除：
- 完全重复
- 明显过时，且已有新版本
- 已被主记忆完整吸收

### 2.2 保留但整合
满足以下条件不直接删，而是整合进主记忆：
- 有独特信息，但表达零散
- 是阶段性结论，但仍有长期参考价值
- 是项目历史中的关键约束

### 2.3 不删除
以下情况默认不删：
- 用户要求保留历史版本
- 记忆含关键信息但当前无法安全判断是否过时
- 无法精确定位旧记忆块，删除可能误伤其他内容

遇到不确定情况，先问用户，不强删。

## 3️⃣ 主记忆结构模板

### 3.0 主记忆质量标准
主记忆应尽量满足：
- **标题唯一明确**：一眼能看出主题
- **bullet 数量控制在 4~8 条**：太少信息不够，太多容易变流水账
- **一条 bullet 只表达一个稳定结论**
- **优先写当前有效规则**，不要堆太多历史过程
- **总长度适中**：能被下次任务快速扫读
- **避免重复表述**：相近内容合并成一条
- **必要时才写“已废弃/历史说明”**，且应简短

如果整理后的主记忆出现以下情况，说明质量不够好：
- 超过 10 条 bullet
- 多条 bullet 只是同一句话换说法
- 大量记录时间线过程，而不是当前有效规则
- 不看原上下文就读不懂

### 3.1 已有主记忆时的更新模板
若该主题已经存在主记忆，优先按以下方式处理：

```text
读取旧主记忆
→ 合并新信息
→ 去掉过时点
→ 保留同一标题
→ 更新为最新唯一版本
```

示例：
- 已有：`## UnifiedVIP 项目总备忘录`
- 新增：新的约束 / 新完成项 / 新执行偏好
- 正确做法：更新这条总备忘录
- 错误做法：再新建一条 `## UnifiedVIP 最新补充`

### 3.2 项目型记忆
```md
## 项目名 项目总备忘录
- 正式工作目录：...
- 当前主验证方式：...
- 已确认的关键约束：...
- 当前推荐流程：...
- 已废弃/不再推荐：...
```

### 3.3 偏好型记忆
```md
## 主题偏好
- 用户偏好：...
- 默认执行方式：...
- 不再使用的旧规则：...
```

### 3.4 工作流型记忆
```md
## 主题工作流约定
- 默认步骤：...
- 例外情况：...
- 风险点：...
- 当前最新版本：...
```

## 4️⃣ 实现约束（非常重要）

### 4.1 Minis 原生限制
- `memory_write` 只能**追加写入**
- `memory_get` 只能**检索**
- 要删除旧记忆，必须通过读取 `/var/minis/memory/*.md` 后再用 `file_edit` 修改文件

### 4.2 删除前必须备份
每次改 memory 文件前必须：
1. 先 `file_read` 确认内容
2. 再备份原文件
3. 再用 `file_edit` 精确删除旧记忆块

### 4.3 删除必须可精确定位
- 只有在能准确定位旧记忆块时，才允许删除
- 如果无法唯一匹配，宁可不删，改为提示用户手动确认

### 4.4 推荐辅助脚本
技能内置辅助脚本：
- `references/scan_memory_topic.sh`：扫描某主题相关 memory 文件
- `references/build_master_memory.sh`：从扫描结果生成主记忆草稿
- `references/backup_memory_files.sh`：删除前备份相关 memory 文件
- `references/locate_memory_blocks.sh`：按关键词定位候选记忆块，帮助安全删除

推荐调用顺序：
```text
scan_memory_topic.sh
→ build_master_memory.sh
→ locate_memory_blocks.sh
→ 用户确认
→ backup_memory_files.sh
→ file_edit 删除旧记忆
→ memory_write / 更新主记忆
```

### 4.5 回滚流程
如果删除后发现误删或主记忆整理结果不理想：
1. 找到对应 memory 文件的 `.bak-时间戳` 备份
2. 用备份覆盖当前 memory 文件恢复原状
3. 缩小主题范围后重新整理
4. 必要时改为“只生成主记忆，不自动删除”

## 5️⃣ 冲突处理规则

### 5.1 新主记忆与旧记忆冲突时
- 以**最新、明确、用户确认**的内容为准
- 旧记忆若已无价值，删除
- 旧记忆若有历史参考价值，则在主记忆中简短保留“旧规则已废弃”说明

### 5.2 冲突决策树
- **新版本更明确** → 保留新版本，删除旧版本
- **旧版本部分仍有效** → 融合进主记忆
- **两个版本分场景成立** → 主记忆中拆分场景说明
- **无法判断** → 先问用户，不删除

## 6️⃣ 敏感信息规则

即使在“整理为单独记忆存储”的场景下，以下内容仍默认禁止写入：
- 密码
- API Key
- Token
- 私钥
- 验证码
- 环境变量明文

若用户强烈要求，也必须先警告风险，再等待明确确认。

## 6.1 反例区（常见错误做法）

### 反例 1：把搜索结果原样拼进主记忆
错误示例：
```md
## 某项目总备忘录
- 2026-04-11 说了这个
- 2026-04-12 又说了那个
- 2026-04-13 继续补充……
```
问题：只是拼接流水账，没有提炼出当前有效规则。

### 反例 2：因为关键词命中就误删别的主题
错误示例：
- 搜“备份”时，把所有含“备份”的项目记忆都删掉。

问题：关键词相似不等于主题相同，容易误删无关主记忆。

### 反例 3：已有主记忆却继续新建同主题条目
错误示例：
- 已有 `## UnifiedVIP 项目总备忘录`
- 又新增 `## UnifiedVIP 最新补充`

问题：会重新制造碎片化记忆，违背归并目标。

### 反例 4：把临时状态写进长期主记忆
错误示例：
```md
- 今天下午测试卡住了
- 刚才网络断了一次
```
问题：这是临时状态，不是长期稳定规则。

### 反例 5：主记忆过长、超过 10 条 bullet
问题：下次检索时难以快速扫读，反而增加噪音。

### 反例 6：未备份就直接删旧记忆
问题：一旦误删，难以快速恢复。

## 7️⃣ 标准执行输出

### 7.0 删除候选清单（确认前推荐输出）
```md
待删除候选：
- 文件：YYYY-MM-DD.md
  标题：某条旧记忆标题
  原因：已被主记忆吸收 / 已过时 / 重复表达
- 文件：YYYY-MM-DD.md
  标题：另一条旧记忆标题
  原因：与主记忆重复
```

### 7.1 整理成功
```md
已将相关记忆整理为 1 条主记忆：<主题>
并已删除其他重复/过时的相关记忆。
后续我会优先以这条主记忆为准。
```

### 7.2 仅整理未删除
```md
我已整理出主记忆：<主题>
但由于部分旧记忆无法安全精确删除，暂未自动移除。
如需要，我可以继续帮你人工确认后清理。
```

### 7.3 因风险暂停
```md
这次整理会涉及删除旧记忆。
在继续前，我需要你的确认；删除前我会先备份相关 memory 文件。
```

## 8️⃣ 推荐调用策略

### 用户要求“整理成一个”
- 直接触发本技能
- 识别主题边界
- 搜索全部相关记忆
- 合并出主记忆
- 备份后清理旧记忆

### 用户要求“删除其他相关记忆”
- 不单独暴力删除
- 必须先生成主记忆或确认保留项
- 再删除其他重复/过时条目

### 推荐伪流程
```text
确定主题
→ memory_get 全量检索
→ 分组：有效 / 过时 / 重复 / 待整合
→ 生成主记忆草稿
→ 用户确认
→ 备份相关 memory 文件
→ 写入主记忆
→ 删除其他相关旧记忆
→ 回复整理结果
```

## 9️⃣ 技能自检清单

- 是否真的把同类记忆收拢成一条主记忆？
- 是否先做了全量检索，而不是凭印象删？
- 删除前是否已备份相关 memory 文件？
- 删除是否精确、安全、可回退？
- 主记忆是否足够清晰、短、稳？
- 是否保留了必要但不冗余的长期信息？

## 9.1 质量评分参考（自评用）
| 维度 | 满分 | 标准 |
|---|---:|---|
| 主题边界清晰 | 10 | 能明确知道在整理哪个主题 |
| 全量检索完整 | 15 | 相关记忆基本都被检出 |
| 主记忆质量 | 20 | 主记忆清晰、稳定、可复用 |
| 删除安全性 | 20 | 删除前备份、删除定位准确 |
| 去重效果 | 15 | 旧噪音明显减少 |
| 敏感信息控制 | 10 | 未把敏感信息写入主记忆 |
| 用户确认机制 | 10 | 高风险删除前有确认 |

目标：**≥ 85 分** 才算整理质量较好。
