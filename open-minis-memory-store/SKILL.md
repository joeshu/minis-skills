# open-minis-memory-store

一个用于**整理、归并、更新、清理旧记忆**的执行型技能。
目标：把某个主题下分散的旧记忆收拢成一个**主记忆**，并在安全前提下清理重复、过时、被覆盖的旧记忆。

## 触发词
- 把这些记忆整理成一个
- 合并相关记忆
- 清理重复记忆
- 删除旧记忆
- 把某主题记忆收拢一下
- consolidate memories / merge memory entries / clean old memories

## 输入
- 当前主题（项目 / 偏好 / 工作流 / 长期主题）
- 相关关键词
- 是否允许清理旧记忆
- 是否保留历史版本

## 输出
默认返回：
1. 该主题的主记忆草稿
2. 候选旧记忆清单
3. 删除/保留建议
4. 若继续执行，给出归并与清理计划

## 核心原则
- **先查全量，再归并**
- **只有在用户明确允许且可安全定位时才清理旧记忆**
- **执行破坏性清理前先备份相关 memory 文件**
- **默认保留一个主记忆**
- **宁可少删，也不要误删**
- **不确定时先更新主记忆，不直接删旧块**

## 工作流

### 决策树
1. 先判断当前主题是否已有多条零散记忆。
2. 若没有，不必强行归并。
3. 若有，先扫描相关记忆。
4. 先生成主记忆草稿。
5. 再判断哪些旧记忆可以删除、哪些只能保留合并。
6. 删除前必须先备份。

### Phase 1: 确定主题边界
先明确这次整理的是：
- 某个项目
- 某类偏好
- 某组工作规则
- 某个长期主题

### Phase 2: 检索相关记忆
1. 提取 2~6 个稳定关键词
2. 用 `memory_get` 搜相关记忆
3. 记录匹配结果来自哪些文件/日期
4. 分类为：
- 当前仍有效
- 已过时
- 重复表达
- 可并入主记忆

### Phase 3: 生成主记忆草稿
主记忆应：
- 标题唯一明确
- bullet 控制在 4~8 条
- 一条 bullet 只表达一个稳定结论
- 优先保留当前有效规则
- 避免重复表述

### 主记忆模板
```md
## 主题总备忘录
- 当前有效规则 1
- 当前有效规则 2
- 关键偏好 / 结论 3
- 如有必要，补充已废弃说明
```

### Phase 4: 删除与归并判断
#### 可直接删除
- 完全重复
- 明显过时且已被新版本覆盖
- 已被主记忆完整吸收

#### 只归并不删除
- 有独特信息但表达零散
- 属于阶段性结论但仍有参考价值
- 无法精确定位旧块，怕误删

#### 默认不删
- 用户要求保留历史版本
- 无法确认是否过时
- 可能误伤其他主题内容

### Phase 5: 备份与执行
- 删除前必须先备份相关 memory 文件
- 能精确定位旧块时才删
- 若已有主记忆，优先更新旧主记忆，不重复新建主记忆

## 输出风格
- 默认先给主记忆草稿
- 再列候选旧记忆清单
- 再给删除/保留建议
- 不默认直接删

## 响应模板
### 主记忆模板
- `我已整理出该主题的主记忆草稿。`

### 清理建议模板
- `这些旧记忆属于重复/过时项，建议在备份后清理。`

### 保留建议模板
- `这些旧记忆仍有独特信息，建议并入主记忆或保留观察。`

### 风险模板
- `当前无法安全定位旧记忆块，建议先不自动删除。`

## 与其他记忆技能的分工
- `open-minis-memory-store`：负责**整理、归并、去重、清理旧记忆**
- `memory-topic-router`：负责**在任务执行前决定优先读取哪类记忆来源**
- `memory-layer-governor`：负责**新信息该写哪层**
- `memory-write-gatekeeper`：负责**写入前审查**
- `memory-dedup-auditor`：负责**先审计后整理**

## 风险与反例
- 未扫描全量相关记忆就直接归并
- 未备份就删 memory 文件
- 无法精确定位却强删旧块
- 明明是更新主记忆，却重复新建多个主记忆
- 误删相似词但不同主题的记忆
