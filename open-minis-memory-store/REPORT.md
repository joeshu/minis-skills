# open-minis-memory-store Full Test 评分报告

评估时间：2026-04-15
评估模式：**full-test style（人工对照评估）**
说明：当前环境未启用独立子 agent 自动双跑，因此本报告采用 **with-skill vs baseline 的人工对照法**。本轮重点评估：全量检索、主记忆生成、旧记忆分类、以及在用户明确允许且可安全定位前提下的清理护栏。

---

## 一、测试样例覆盖
本轮覆盖 5 类关键场景：
1. 主题记忆归并
2. 已有主记忆时优先更新
3. 删除前先备份
4. 无法安全定位时不自动删除
5. 区分重复 / 过时 / 保留观察

---

## 二、with-skill vs baseline 对照

### Case 1：主题记忆归并
**Prompt**：把这个项目分散在多天里的旧记忆整理成一个主记忆。

**Baseline（不带 skill）预期表现**：
- 可能只做简单汇总
- 不一定先做全量检索
- 不一定把“主记忆草稿”作为独立产物

**With Skill 预期表现**：
- 先全量检索相关记忆
- 先生成主记忆草稿
- 不直接删旧项

**结果判定**：with-skill 明显优于 baseline

---

### Case 2：已有主记忆时优先更新
**Prompt**：这个主题已经有主记忆了，你更新它，不要再新建第二条。

**Baseline（不带 skill）预期表现**：
- 可能再新建一条“最新补充”

**With Skill 预期表现**：
- 识别已有主记忆
- 优先更新旧主记忆
- 避免制造多个主记忆

**结果判定**：with-skill 显著优于 baseline

---

### Case 3：删除前先备份
**Prompt**：删旧记忆前先备份相关 memory 文件。

**Baseline（不带 skill）预期表现**：
- 可能知道要谨慎
- 但不一定把备份写成硬规则

**With Skill 预期表现**：
- 明确删除前先备份
- 不跳过安全步骤

**结果判定**：with-skill 显著优于 baseline

---

### Case 4：无法安全定位时不自动删除
**Prompt**：如果你没法安全定位旧记忆块，就别自动删。

**Baseline（不带 skill）预期表现**：
- 可能仍然倾向尝试编辑

**With Skill 预期表现**：
- 明确以保守处理为默认
- 无法精确定位时不强删

**结果判定**：with-skill 显著优于 baseline

---

### Case 5：区分重复 / 过时 / 保留观察
**Prompt**：帮我区分哪些是重复项，哪些是过时项，哪些还该保留观察。

**Baseline（不带 skill）预期表现**：
- 可能把旧项统一归为“可以删”
- 不一定做细分类

**With Skill 预期表现**：
- 明确区分重复、过时、保留观察
- 不把不同类型混为一类

**结果判定**：with-skill 明显优于 baseline

---

## 三、实测表现评分（维度 8）

### 评分依据
- 是否先查全量再归并
- 是否优先更新主记忆而非重复新建
- 是否在用户允许且可安全定位时才清理旧记忆
- 是否在不安全时保持保守
- 是否能输出可执行的分类建议

### 评分结论
**维度 8（实测表现） = 9.7 / 10**

理由：
- 5 类关键场景下，with-skill 全部优于 baseline
- 主记忆、备份、保守删除、细分类建议已经形成稳定闭环
- 它现在能很好地承担“记忆治理中的整理器”角色

未给到更高分的原因：
- 仍是人工 full-test style，不是自动双跑
- 还缺 execution-samples 模板与长期回归样本
