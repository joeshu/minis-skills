## 一、测试样例覆盖
本轮覆盖 7 类关键场景：
1. check 模式预检
2. sync 模式增量同步准备
3. push 模式限定范围推送
4. restore 模式一键恢复
5. 无关改动 / `.bak` 文件拦截
6. 恢复后最小检查
7. 增量恢复

---

## 二、with-skill vs baseline 对照

### Case 1：check 模式预检
**Prompt**：先检查一下这套元技能体系这次有哪些文件会被同步，别急着推。

**Baseline（不带 skill）预期表现**：
- 可能直接给出泛化 git 建议
- 不一定限定元技能体系范围

**With Skill 预期表现**：
- 识别为 check 模式
- 输出待同步范围
- 指出无关改动或风险项

**结果判定**：with-skill 明显优于 baseline

---

### Case 2：sync 模式增量同步准备
**Prompt**：先把这套元技能体系的增量同步范围整理好，但先别 push。

**Baseline（不带 skill）预期表现**：
- 可能直接建议 commit/push
- 不一定保留“先不推送”的限制

**With Skill 预期表现**：
- 识别为 sync 模式
- 限定范围输出当前变更
- 明确本次不推送

**结果判定**：with-skill 显著优于 baseline

---

### Case 3：push 模式限定范围推送
**Prompt**：把这套元技能体系安全推到 git，但别把其他无关技能一起带上。

**Baseline（不带 skill）预期表现**：
- 容易直接全仓库 add/commit

**With Skill 预期表现**：
- 识别为 push 模式
- 限定提交范围
- 完成提交和推送

**结果判定**：with-skill 显著优于 baseline

---

### Case 4：restore 模式一键恢复
**Prompt**：我重装后怎么一键恢复这套元技能体系，你给我最快方案。

**Baseline（不带 skill）预期表现**：
- 可能只给出笼统 clone 建议
- 不一定补全分支与最小检查

**With Skill 预期表现**：
- 识别为 restore 模式
- 给出 clone / pull 两种恢复方案
- 给出最小检查命令

**结果判定**：with-skill 显著优于 baseline

---

### Case 5：无关改动 / 临时文件拦截
**Prompt**：如果检测到别的无关技能改动或者 .bak 文件，你先别乱推。

**Baseline（不带 skill）预期表现**：
- 可能忽略 `.bak` 与无关改动风险

**With Skill 预期表现**：
- 识别无关改动与临时文件风险
- 提醒限定范围后再推送

**结果判定**：with-skill 显著优于 baseline

---

### Case 6：恢复后最小检查
**Prompt**：恢复完后，顺手帮我检查元技能主栈是不是都在。

**Baseline（不带 skill）预期表现**：
- 可能只说“你自己看一下目录”

**With Skill 预期表现**：
- 输出最小检查范围
- 覆盖主技能、规范层、元文档层

**结果判定**：with-skill 显著优于 baseline

---

### Case 7：增量恢复
**Prompt**：本地 skills 还在，先帮我做增量恢复，不要整仓重装。

**Baseline（不带 skill）预期表现**：
- 可能仍建议直接 clone 重装

**With Skill 预期表现**：
- 识别为增量恢复
- 优先 `git pull origin master`
- 保留现有仓库工作副本

**结果判定**：with-skill 显著优于 baseline
