# open-minis-output-governor

用途：决定结果该怎么展示和保存，并把“是否落盘、落到哪里、用什么形式展示、聊天里保留多少”拆成可执行决策。

## 核心问题
这个技能主要回答 4 个问题：
1. **要不要落盘**
2. **落到哪里**（shared / workspace / attachments / 不落盘）
3. **用什么形式**（聊天 / Markdown / HTML / attachment）
4. **聊天里保留多少内容**（完整解释 / 1~3 句摘要 / 最小一句）

## 默认顺序
1. 先判断用户是否明确要求文件 / 页面 / 附件
2. 再判断结果是否需要跨会话继续使用
3. 再判断内容本质更适合 Markdown、HTML 还是 attachment
4. 最后压缩聊天体积，避免文件与聊天双重长篇重复

## 快速路由
- 只看一句话：聊天
- 结构化总结：Markdown
- 页面化展示：HTML
- 图表/图片/音视频：attachment
- 以后还要继续用：shared
- 当前临时调试：workspace
- 既要结论又要产物：聊天摘要 + 文件链接
- 只要文件不要长解释：文件优先 + 最小聊天摘要

## 决策优先级
当多个信号同时出现时，按以下顺序裁决：
1. 用户明确要求
2. 生命周期（长期 / 临时）
3. 展示形式匹配度
4. 聊天负担最小化
5. 组合输出优先于单一路径误伤

## 关键原则
- 先判断“要不要落盘”
- 再判断“落在哪里”
- 再判断“用什么形式展示”
- 默认优先给一句聊天摘要，再按需附文件链接
- 若结果既要简洁结论又要后续复用，优先“聊天摘要 + 文件链接”组合
- 若文件已足够，不在聊天里重复铺开完整内容
- shared 用稳定命名；workspace 放中间产物；attachment 只用于真正要预览的媒体

## 常见误区
- 该长期保留的结果却只留在聊天里
- 中间调试文件误写到 shared
- 纯文本长报告被硬做成 HTML
- 用户只要一句结论，却被强行生成复杂文件
- 文件已写好，还在聊天重复输出整份内容
